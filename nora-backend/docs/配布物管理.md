# 配布物管理

このドキュメントは、NoraOps の配布物（`uv.exe` / PortableGit / 将来のVS Code拡張配布ファイル）を  
`nora-backend/data/tools` 配下で一元管理するための運用手順を定義する。

**アプリ側（Gitea Release で配る zip / manifest）は別規約。** [アプリ実行契約](app-manifest-contract.md) を参照。

## 1. 結論（よくある質問）

- Q: `uv-x86_64-pc-windows-msvc.zip` を展開したがどう置く？
  - A: 展開後の `uv.exe` **単体**を配置する。
  - 配置先例: `data/tools/uv/0.6.0/uv.exe`

- Q: Git for Windows は何を置く？
  - A: 公式の Portable 配布物（`.7z.exe`）をそのまま配置できる。
  - 配置先例: `data/tools/git/2.54.0/PortableGit-2.54.0-64-bit.7z.exe`

## 2. ルート構成

```text
nora-backend/
  data/
    tools/
      windows-x64/
        manifest.json
      uv/
        0.6.0/
          uv.exe
      git/
        2.54.0/
          PortableGit-2.54.0-64-bit.7z.exe
      extension/
        0.1.0/
          softrail-client-0.1.0.vsix
```

## 3. ダウンロード元と配置ルール

### 3.1 uv.exe
- **正の取得元（NoraOps 運用）**:
  - https://github.com/astral-sh/uv/releases
- Windows x64 の配布zip（例: `uv-x86_64-pc-windows-msvc.zip`）を取得し、展開。
- **展開後の `uv.exe` のみ**を配置する。
- 配置規約:
  - `data/tools/uv/<version>/uv.exe`

### 3.2 PortableGit
- **正の取得元（NoraOps 運用）**:
  - https://github.com/git-for-windows/git-snapshots/releases
- Portable 向けアセット（例: `PortableGit-2.54.0-64-bit.7z.exe`）を取得。
- 現在の拡張実装は `.7z.exe` を自己解凍実行できるため、**そのまま配置可能**。
- 配置規約:
  - `data/tools/git/<version>/PortableGit-<version>-64-bit.7z.exe`

### 3.3 VS Code拡張（将来）
- 拡張をビルドして `.vsix` を出力。
- 配置規約（推奨）:
  - `data/tools/extension/<version>/softrail-client-<version>.vsix`
- トップページの配布リンクやmanifestを切り替えて配布する。

## 4. インストール先（サーバ正本 vs 各 PC）

NoraOps のツールは **2 か所** に存在しうる。社内で資産として一元管理するのは **サーバ正本のみ**。

| 層 | 役割 | uv | git（実行ファイルまで） |
|----|------|-----|-------------------------|
| **サーバ正本** | 社内マスター・FastAPI が配る | `data/tools/uv/<ver>/uv.exe` | 配布物は `…/PortableGit-….7z.exe`。PC 上で展開後 `…/portable-git/cmd/git.exe` |
| **各 PC** | 拡張がコピーした実行環境 | `%LOCALAPPDATA%\NoraOps\runtime\tools\uv\uv.exe` | `%LOCALAPPDATA%\NoraOps\runtime\tools\portable-git\cmd\git.exe` |

- サーバに **git.exe を直接置く運用はしない**（PortableGit インストーラを置き、クライアントが展開する）。
- PC 側だけ消す: `Remove-Item -Recurse -Force $env:LOCALAPPDATA\NoraOps\runtime`
- サーバ正本を消す: `data/tools/uv/<ver>` / `data/tools/git/<ver>` フォルダを削除し manifest を更新。

導入の全体像: [NoraOps/NoraOpsの導入.md](../../NoraOps/NoraOpsの導入.md)

## 5. manifest.json と sha256

対象ファイル:

- `data/tools/windows-x64/manifest.json`

### 5.1 sha256 とは何か

`manifest.json` 内の `uv.sha256` / `portableGit.sha256` は、**そのエントリの `url` が指すファイル 1 個**についての **SHA-256 ダイジェスト（16進小文字 64 文字）** である。

| 観点 | 説明 |
|------|------|
| **目的** | クライアントが FastAPI からファイルを DL したあと、**同じ内容か**を検証する（通信エラー・キャッシュ破損・誤ったファイル配置の検知） |
| **目的ではない** | uv / Git 公式が発行するデジタル署名の検証ではない。CVE 修正の可否判定でもない |
| **誰が決めるか** | **社内運用** — サーバに置いた「この版のこのファイル」の指紋を manifest に書く |
| **いつ変えるか** | 配布ファイルの **バイト内容が 1 バイトでも変わったとき**（再ダウンロード・差し替え・バージョンアップすべて） |

### 5.2 設定基準（運用ルール）

1. **対象ファイルを確定する**  
   - uv: `data/tools/uv/<version>/uv.exe`（zip 展開後の exe のみ）  
   - git: `data/tools/git/<version>/PortableGit-….7z.exe`（manifest の URL と同じパス上のファイル）

2. **配置後にハッシュを取る**（配置前の想定値や公式サイトの値は使わない）

```powershell
(Get-FileHash -Path "<配置したファイルのフルパス>" -Algorithm SHA256).Hash.ToLower()
```

3. **manifest に書く値**
   - `sha256`: 上記の **64 文字・小文字 hex**（`aaaaaaaa…` などのダミーは不可）
   - `size`: `(Get-Item "<ファイル>").Length` の **実測バイト数**
   - `version` / `url`: フォルダ名・URL パスと **一致**させる

4. **検証の流れ（クライアント）**
   - manifest 取得 → `url` から DL → 一時ファイルに対して SHA-256 計算 → manifest の `sha256` と **完全一致**しなければインストール中止

5. **よくあるミス**
   - exe を差し替えたが sha256 を古いままにした → `checksum mismatch`
   - zip を展開する前の zip 本体のハッシュを uv に書いた → 不一致
   - 大文字 hex のまま書いた → 実装は小文字比較（小文字で統一）

### 5.4 手順: 値を確認して manifest.json に入れる

**詳細手順書（推奨）**: [NoraOps/manifest-jsonの書き方.md](../../NoraOps/manifest-jsonの書き方.md)

**自動反映（配置済みファイルから一括）**:

```powershell
cd nora-backend
powershell -ExecutionPolicy Bypass -File .\scripts\update-tools-manifest.ps1 `
  -BaseUrl "http://127.0.0.1:8000" -UvVersion "0.6.0" -GitVersion "2.54.0"
```

**手動で確認だけする場合**:

```powershell
cd nora-backend
$f = "data\tools\uv\0.6.0\uv.exe"
"sha256=$((Get-FileHash $f -Algorithm SHA256).Hash.ToLower())"
"size=$((Get-Item $f).Length)"
```

出た文字列を `manifest.json` の `uv.sha256` / `uv.size` にコピーする（git も同様）。

### 5.5 その他の manifest キー

- `uv.version` / `portableGit.version` — 配布フォルダ名・URL パスと一致させる論理バージョン
- `policy.forceMinimumUvVersion` / `forceMinimumGitVersion` — クライアントに記録された版がこれ未満なら **再セットアップを促す**（緊急の脆弱性後進用。sha256 とは別軸）

## 6. manifest.json 編集ルール（一覧）

主要キー:

- `uv.version` / `uv.url` / `uv.sha256` / `uv.size`
- `portableGit.version` / `portableGit.url` / `portableGit.sha256` / `portableGit.size`
- `policy.forceMinimumUvVersion`
- `policy.forceMinimumGitVersion`

URLの基本形式:
- uv: `http://<host>/api/tools/files/uv/<version>/uv.exe`
- git: `http://<host>/api/tools/files/git/<version>/PortableGit-<version>-64-bit.7z.exe`

更新手順（重要）:
1. 新しい配布ファイルを `data/tools/...` に配置
2. `sha256` と `size` を実ファイル基準で算出
3. `manifest.json` の `version/url/sha256/size` を更新
4. サーバ起動後に URL が 200 で取得できることを確認
5. クライアントで初回導入 or 更新導入を確認

## 7. 複数バージョン配置時の挙動

- `data/tools/uv/` や `data/tools/git/` に複数バージョンがあっても問題ない。
- ただし、クライアントが使うのは **manifest が指す1バージョンのみ**。
- 自動で最新フォルダ探索はしない（manifest駆動）。

つまり:
- `0.6.0` と `0.6.1` が並んでいても、manifestが `0.6.0` を指せば `0.6.0` が使われる。

## 8. 未配置/不整合時の挙動

### 8.1 URL先ファイルが未配置
- `GET /api/tools/files/...` が 404 を返す。
- クライアント側は初回導入時にダウンロード失敗でエラー表示する。

### 8.2 ハッシュ不一致
- ダウンロード後に `sha256` 検証で停止。
- クライアント側はインストール中断してエラー表示する。

### 8.3 PortableGitの中身不正
- 自己解凍後に `cmd/git.exe` が見つからない場合、インストール失敗になる。

## 9. 切り替え手順（運用）

### 9.1 ツールのバージョン切替（uv/git）
1. 新バージョンの配布物を `data/tools/uv/<new>` / `data/tools/git/<new>` に配置
2. `manifest.json` を新バージョンへ更新
3. `policy.forceMinimum*` を必要に応じて引き上げ
4. スモークテスト後に本番反映

### 9.2 VS Code拡張配布リンク切替（将来）
1. 新しい `.vsix` を `data/tools/extension/<new>/...vsix` に配置
2. トップページ用設定（`SOFTRAIL_CLIENT_DOWNLOAD_URL`）を新URLへ更新
3. 必要なら旧バージョンURLも残し、段階移行する

## 10. 推奨チェックリスト

- [ ] ファイル配置先が規約どおり
- [ ] `manifest.json` の `url` が正しい
- [ ] `sha256` と `size` が実ファイルと一致
- [ ] `GET /api/tools/files/...` が 200 を返す
- [ ] クライアント初回導入で `uv` / `git` が正常配置される

## 11. PowerShell: sha256 / size 算出と manifest 反映

`sha256` は **§5** のとおり、配置済み実ファイルの指紋。`size` は配布確認と進捗表示のため推奨。

### 11.1 単体ファイルの sha256 / size を取得

```powershell
$file = ".\data\tools\git\2.54.0\PortableGit-2.54.0-64-bit.7z.exe"
$hash = (Get-FileHash -Path $file -Algorithm SHA256).Hash.ToLower()
$size = (Get-Item -Path $file).Length
"sha256=$hash"
"size=$size"
```

### 11.2 manifest を自動更新（git・個別）

> 両方まとめて更新するなら `scripts\update-tools-manifest.ps1`（§5.4）を使う。

```powershell
$manifestPath = ".\data\tools\windows-x64\manifest.json"
$filePath = ".\data\tools\git\2.54.0\PortableGit-2.54.0-64-bit.7z.exe"
$version = "2.54.0"
$url = "http://127.0.0.1:8000/api/tools/files/git/2.54.0/PortableGit-2.54.0-64-bit.7z.exe"

$hash = (Get-FileHash -Path $filePath -Algorithm SHA256).Hash.ToLower()
$size = (Get-Item -Path $filePath).Length

$json = Get-Content -Path $manifestPath -Raw | ConvertFrom-Json
$json.portableGit.version = $version
$json.portableGit.url = $url
$json.portableGit.sha256 = $hash
$json.portableGit.size = $size
$json.generatedAt = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")

$json | ConvertTo-Json -Depth 10 | Set-Content -Path $manifestPath -Encoding UTF8
```

### 9.3 manifest を自動更新（uv）

```powershell
$manifestPath = ".\data\tools\windows-x64\manifest.json"
$filePath = ".\data\tools\uv\0.6.0\uv.exe"
$version = "0.6.0"
$url = "http://127.0.0.1:8000/api/tools/files/uv/0.6.0/uv.exe"

$hash = (Get-FileHash -Path $filePath -Algorithm SHA256).Hash.ToLower()
$size = (Get-Item -Path $filePath).Length

$json = Get-Content -Path $manifestPath -Raw | ConvertFrom-Json
$json.uv.version = $version
$json.uv.url = $url
$json.uv.sha256 = $hash
$json.uv.size = $size
$json.generatedAt = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")

$json | ConvertTo-Json -Depth 10 | Set-Content -Path $manifestPath -Encoding UTF8
```
