CMS

セクションを選んで編集・確認します。チェックルールの ON/OFF、プロンプト、AI 中継の状態を管理できます。

メンテ方針: チェックの実行定義は *.rules.json（1か所）。 CMS 表示用メタデータは check_catalog.py（必須フラグ・説明・実行タイミング）。 CMS が書くのは {{ toggles_file }} の ON/OFF のみ — ルール本文の二重管理は不要です。

Gitea 保存・公開の運用（ブランチ・版番号・履歴）

Creator の保存は拡張が workspace 全体の zip を送り、サーバーが Gitea に git push します（差分送信ではありません）。

操作ブランチ（既定）履歴備考
通常保存 noraops-draft 残さない（force push） 下書きの最新だけ。Gitea の branch が増えません。
公開リリース main 残す 既存 main を clone → zip で置換 → commit → 通常 push

公開時の版番号（拡張が入力する semver、例 1.2.0）:

  1. サーバーが DB の最新公開版と比較し、同じ版・下げる版は拒否（例: 既に v1.2.0 なら v1.2.1 以上のみ）
  2. Gitea の main に commit を push（履歴付き）
  3. Git タグ v1.2.0 を付与して push
  4. topic nora-published を付与
  5. タグ付きソースから Runner 用 artifact zip を生成し、DB PublishedVersion に記録

ミス例: 版番号を上げ忘れる / 既存版と同じ番号 → 公開 API が 400 で拒否。main の履歴は壊れません。

環境変数: NORAOPS_SAVE_DRAFT_BRANCH · NORAOPS_SAVE_PUBLISH_BRANCH

CMS 全体の使い方（必須・反映タイミング・よくあるミス）
セクションCMS で変えるもの反映ミスったとき
ポリシーチェック ON/OFF のみ 即時（拡張が次回 bundle 取得） 必須項目を OFF にしようとしても UI で不可

基本プロンプトカタログ

使い方・各項目の意味・ミスったとき

オフライン時は拡張同梱版を使用。オンライン時はここで編集したカタログが {{ builtin_catalog_api_path }} 経由で配布されます。内容を変えたら version を上げてください（拡張が新しい版と判断するため）。

項目必須いつ変えるミスったとき
version 必須 プロンプト追加・本文変更のたびに bump（例 0.21.1 → 0.21.2） 上げ忘れ → 拡張が「最新です」と表示し続けることがある
key 必須 新規追加時のみ（後から変更非推奨） 重複・形式不正 → 保存 400。既存ユーザの有効状態と紐づく
title 必須 UI 表示名を変えたいとき 空 → 保存 400
category 必須 creator（Creator 用）/ xllm（xLLM 用）/ custom 不正値 → 保存 400
order 必須 一覧の並び順 同じ数字 → key 順でソート
showInXllm 任意 xLLM「① プロンプトを作る」に出すか OFF → ボタンに出ない（有効でも非表示）
defaultEnabled 任意 新規 WS で最初から ON にするか OFF → ユーザが Prompt タブで有効化が必要
dynamic 任意 本文を拡張が WS から生成する場合（モック / 0→1 / 環境など） ON のとき body は無視される（null 保存）
resolver 任意 動的プロンプトの生成ロジック名（拡張実装と一致させる） 未知の resolver → 空本文やフォールバック
body 静的のみ 固定文面のプロンプト 空の静的 → コピーしても中身なし

手順: 行を編集 →「一覧に反映」→「カタログを保存」。保存先: {{ builtin_catalog_file }}

拡張の Prompt タブ「基本プロンプト」と xLLM ボタンに配布されます。 API: {{ builtin_catalog_api_path }} · 保存先: {{ builtin_catalog_file }}
