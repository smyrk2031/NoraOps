# NoraOps 開発時用の動作手順書

**誰向け**: このリポジトリ（`NoraOps`）を触って、拡張・FastAPI・Gitea 連携を**手元で試す**人向けです。  
**ゴール**: 「何を、どの順で、どう起動すればよいか」が迷子にならないこと。

導入・本番運用・ツールの公式 DL 元: [NoraOpsの導入.md](./NoraOpsの導入.md)

テスト・動作確認: [テストと動作確認.md](./テストと動作確認.md)（GUI / `npm test` / `pytest`）

拡張 F5 後: 画面下 **Creator** / **Runner** で各タブを開く。起動時は両タブが自動で開く（`noraops.runner.autoOpenPanels`）。

> **注（2026-06）**: `.nora/` や `nora/packages/` の記述は **現行実装**。改定後は AppData とルート pyproject — [ワークスペース設計改定.md](./ワークスペース設計改定.md)／[互換方針.md](./互換方針.md)。

## 0. 全体像（3 つだけ覚える）

| 部品 | フォルダ | 役割 | 開発時に必須？ |
|------|----------|------|----------------|
| **FastAPI** | `nora-backend/` | チェックルール配布・リポ作成 API | オンライン保存・Gitea 自動作成を試すなら **必須** |
| **VS Code 拡張** | `vscode-extension/` | NoraOps4code（保存・チェック・push） | **必須** |
| **Gitea** | （別途インストール/Docker） | Git リモート | push / リポ自動作成を試すなら **必須** |

ローカルだけ（オフライン保存・チェックのみ）なら **拡張だけ** でも動きます（同梱ルール JSON にフォールバック）。

```
[VS Code 拡張] ──HTTP──► [FastAPI :8000] ──API/git──► [Gitea :3000]
       │  zip save            │ artifact zip / rules
       │  artifact GET        │ POST /api/v1/repos/save, /publish
       └─ uv のみ（git 不要）──┘
```

## 2. FastAPI（nora-backend）を起動する

### 2.1 初回セットアップ

PowerShell:

```powershell
cd nora-backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
copy .env.example .env
notepad .env
```

`.env` で最低限直す項目:

| 変数 | 例 | 説明 |
|------|-----|------|
| `GITEA_BASE_URL` | `http://127.0.0.1:3000` | 実在する Gitea の URL（プレースホルダ不可） |
| `GITEA_TOKEN` | scoped PAT（user+repository 書き込み） | リポ作成・**サーバー push**・topic・artifact |
| `NORAOPS_PUSH_SESSION_TTL_MINUTES` | `15` | save/artifact 用短命トークン（分） |
| `NORAOPS_SAVE_MAX_ZIP_MB` | `50` | Creator zip 上限 |
| `GITEA_ORGS` | `my-org` | 組織に作る場合。個人のみなら空で可 |
| `GITEA_LIST_MODE` | `instance` | 既定のままで可 |

### 2.2 起動

```powershell
cd nora-backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

**成功の目安**

- ブラウザで `http://127.0.0.1:8000/api/health` → JSON が返る
- `http://127.0.0.1:8000/api/v1/checks/rules` → `security` / `repoPolicy` を含む JSON
- ターミナルにエラーが出続けない

> **Tip**: このウィンドウは**開きっぱなし**にしておく（止めると拡張の「オンライン」機能がオフライン扱いになる）。

### 2.3 API だけ先に試す（拡張なし）

PowerShell（サーバ起動中）:

```powershell
# チェックルール
Invoke-RestMethod http://127.0.0.1:8000/api/v1/checks/rules

# リポ名チェック（Gitea 設定済みの場合）
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/repos/check-name?name=test-app-001"
```

## 3. Gitea を用意する（push / 自動リポ作成を試す場合）

NoraOps が必要なのは **「ブラウザと API から届く URL」** と **PAT** だけです。  
Gitea の動かし方（`gitea.exe` / Linux バイナリ / Docker）は **本番でも自由** です。**Docker は必須ではありません。**

### 3.1 本番: Windows Server で `gitea.exe`（推奨・Docker 不要）

**結論**: 社内 Windows Server で **`gitea.exe` を常駐サービスとして動かすのは普通どおりの本番構成** です。  
Gitea 公式も Windows 向けバイナリ配布をしています。NoraOps / FastAPI から見れば「HTTPS の Gitea URL が生きているか」だけが重要です。

| やり方 | 開発 | 本番 |
|--------|------|------|
| `gitea.exe` を手動起動（コンソール） | 手元の動作確認には可 | **非推奨**（ログオフで止まる） |
| `gitea.exe` を **Windows サービス** 化 | サーバ上の試験に可 | **推奨** |
| Docker | 手順書の省略用 | 使わなくてよい |

#### 初回インストール（例）

1. [Gitea のダウンロード](https://dl.gitea.com/gitea/) から **Windows amd64** を取得  
2. 例: `C:\gitea\gitea.exe`、データは `C:\gitea\data\`（パスは社内ルールに合わせる）  
3. 初回だけコンソールで起動してセットアップ UI を完了:

```powershell
cd C:\gitea
.\gitea.exe web
```

4. ブラウザで表示された URL（例: `http://サーバ名:3000`）から管理者ユーザーを作成  
5. 以降は **サービス登録** して常駐（手動起動のまま本番にしない）

サービス化の例（どちらか一方でよい）:

- **NSSM** などで `gitea.exe web` をサービス化（よく使われる）  
- または Gitea 付属の `gitea.exe service install`（環境によっては管理者権限が必要）

`custom\conf\app.ini` で本番向けに直す代表項目:

| 設定 | 意味 |
|------|------|
| `DOMAIN` / `ROOT_URL` | ユーザーがアクセスする **実際の URL**（例: `https://git.company.local/`） |
| `HTTP_PORT` / `LOCAL_ROOT_URL` | 裏で listen するポート（リバースプロキシ手前なら 3000 等） |
| `START_SSH_SERVER` | SSH で push するなら `true`（拡張は HTTPS + token でも可） |
| DB セクション | 小規模なら SQLite でも可。ユーザー・リポが増えるなら **PostgreSQL** を推奨 |

#### 本番で足すとよいもの（`gitea.exe` でも同じ）

- **HTTPS**: IIS（ARR）、nginx、Caddy などの前段で TLS 終端  
- **バックアップ**: `data\` フォルダと `custom\conf\app.ini`  
- **ファイアウォール**: 社内 LAN / VPN からだけ 3000（または 443）を開放  
- **PAT**: NoraOps 用に org または bot ユーザーを作り、repo 権限付きトークンを発行  

FastAPI の `GITEA_BASE_URL` と拡張の `noraops.gitea.baseUrl` は、**ユーザーがブラウザで開くのと同じオリジン** に揃えてください（`http://127.0.0.1:3000` のまま本番公開しない）。

> nora-backend の `POST /api/admin/detect-gitea-db` は、サーバ上の `gitea.exe` と `app.ini` から DB 設定を読む補助 API です（Gitea の起動方法とは無関係）。

### 3.2 開発だけ Docker で試す場合（任意）

Docker を使わない場合は **3.1 の `gitea.exe` を手元 PC または開発用 VM で** 同じ手順で十分です。  
どうしてもコンテナで試すときだけ:

```powershell
docker run -d --name gitea -p 3000:3000 gitea/gitea:latest
```

### 3.3 PAT（Personal Access Token）

1. Gitea → ユーザ設定 → Applications → Generate Token  
2. スコープ: **repo**（読み書き）  
3. トークンをコピーして **`nora-backend\.env` の `GITEA_TOKEN` にだけ**入れる

#### スコープ（Gitea 1.26）

| カテゴリ | 設定 |
|---------|------|
| **user** | 読み取りと書き込み（`write:user` — リポ新規作成に必須） |
| **repository** | 読み取りと書き込み（push・topic 付与） |

#### 拡張に PAT は不要（v0.4.0〜）

| 処理 | 経路 |
|------|------|
| リポ作成 | 拡張 → FastAPI → Gitea API |
| **コード送信** | 拡張 → `git bundle` → **`POST /api/v1/repos/push`** → サーバーが `git push` |
| topic 付与 | 拡張 → FastAPI → Gitea API |

短命トークン: `POST /api/v1/noraops/push/sessions` で発行 → push API に付与（既定 15 分）。PAT はサーバー内のみ。

**サーバー要件**: ホストに `git` が PATH にあること（bundle の展開と push に使用）。

#### 拡張の設定（GUI）

**F5 開発ホスト** で `Ctrl + ,` → `noraops server` → **Base Url** のみ（例: `http://127.0.0.1:8000`）。  
`noraops.gitea.token` は空のままでよい。

### 3.4 動作確認

- ブラウザでリポ一覧が見える  
- `nora-backend` の `.env` と拡張設定の URL が**同じオリジン**（例: どちらも `http://127.0.0.1:3000`）

## 4. VS Code 拡張を開発モードで動かす

### 4.0 どのフォルダを開くか（ここがよく混乱する）

| ウィンドウ | 開くフォルダ | 操作 |
|------------|--------------|------|
| **① 開発用（親）** | `vscode-extension` | ここで **F5** を押す（拡張のソースをデバッグ） |
| **② Extension Development Host（子）** | **試したいアプリ用の空フォルダ** など | 保存・Gitea・Python 環境を**実際に試す** |

- **① でリポジトリ全体や `nora-backend` を開いたまま F5** → 動くこともありますが、手順書どおりは **`vscode-extension` だけ** を開いて F5 が確実です。
- **② では `vscode-extension` を開かない**（拡張のソースフォルダで「保存」を試しても、アプリのテストにはなりません）。  
- 例: `D:\work\nora-test-app` のような**別フォルダ**を子ウィンドウで「フォルダを開く」。

```
[① vscode-extension を開く] --F5--> [② 新しい VS Code が開く]
                                          |
                                          +--> ここで D:\work\my-app 等を開いて試す
```

### 4.1 拡張ホストを起動（F5）

**おすすめ（いちばん迷いにくい）**

1. **`vscode-extension` フォルダ**を VS Code / Cursor で開く
2. **`Ctrl + Shift + D`** → ドロップダウンで **`▶ NoraOps拡張を起動（Extension Host）`** → **F5**

**別の開き方（どちらか一方でよい）**

| 開き方 | launch.json の場所 |
|--------|-------------------|
| （任意）マルチルート workspace を開く | ワークスペース内に定義（推奨） |
| `vscode-extension` フォルダだけ開く | `vscode-extension\.vscode\launch.json` |
| リポジトリルートを開く | ルート `.vscode/launch.json`（あれば） |

手順:

1. 上のいずれかで VS Code / Cursor を開く  
2. **`Ctrl + Shift + D`**  
3. ドロップダウンで **`▶ NoraOps拡張を起動（Extension Host）`** を選ぶ（**先に選んでから** F5）  
4. **F5** → **② の新しいウィンドウ**が開く → **4.0 のとおり試験用フォルダを開く**

#### `select-debugger` /「Python Debugger を選んで」と出るとき

**Python・Node・Java は選ばない。** 一覧に **Extension** 系が無いのは、**launch.json が読まれていない**サインです。

| やること | 詳細 |
|----------|------|
| ✅ まずドロップダウンを確認 | `Ctrl+Shift+D` → **▶ NoraOps拡張を起動** があるか。あればそれを選んで F5 |
| ✅ ワークスペースファイルを開く | `noraops-dev.code-workspace` をダブルクリックして開き直す |
| ❌ select-debugger で Python を選ぶ | FastAPI 用。拡張は起動しない |
| ❌ 「launch.json を作成」で Python 用を新規作成 | キャンセルして上記を試す |

**F5 だけ押して** select-debugger が出る → **Esc で閉じる** → 実行とデバッグの **ドロップダウンから拡張用を選んでから** もう一度 F5。

> **Cursor** でも `type: extensionHost` は使えます。出ない場合は一度 **VS Code** で同じ `launch.json` を試すと切り分けできます。

> 初回は PyGarden のツールセットアップ（uv / Portable Git）が走ることがあります。完了まで待つか、`vscode-extension/RUNBOOK.md` を参照。

### 4.2 拡張の設定（② Development Host 側）

**② のウィンドウ**で、コマンドパレット → **Preferences: Open User Settings (JSON)** に追記:

```json
{
  "noraops.server.baseUrl": "http://127.0.0.1:8000",
  "noraops.gitea.baseUrl": "http://127.0.0.1:3000",
  "noraops.gitea.token": "（Gitea PAT）",
  "noraops.save.pushOnSave": true,
  "noraops.tools.manifestUrl": "http://127.0.0.1:8000/api/tools/windows-x64/manifest.json"
}
```

| 設定キー | 意味 |
|----------|------|
| `noraops.server.baseUrl` | FastAPI（チェック・リポ作成 API） |
| `noraops.gitea.baseUrl` / `token` | push 用 |
| `noraops.save.pushOnSave` | 保存のたびに push するか |
| `noraops.tools.manifestUrl` | uv / git 配布 manifest（既定は server + `/api/tools/...`） |

### 4.3 画面の見方（ホーム・保存ボタン）

| UI | 場所 | 出し方 |
|----|------|--------|
| **NoraOps ホーム**（タブ） | エディタのタブ | `Ctrl+Shift+P` → **NoraOps: ホームを開く**、または画面下 **NoraOps** をクリック |
| **保存** | 画面下ステータスバー（左） | 常時表示 `$(save) 保存`（ホームが閉じても消えない） |
| **履歴** | ステータスバー | **NoraOps: 履歴** または `$(history) 履歴` |

**「続きから」を押すとホームタブが消える** → フォルダ切替でウィンドウがリロードされるため（仕様）。  
フォルダを開いたあと **自動でホームが開き直す**（拡張を再読み込み後）。出ないときは上表のとおり **NoraOps** クリックかコマンドで再表示。

> **NoraOps の保存**と **Ctrl+S（ファイル保存）** は別です。クラウドへ送るのは **ステータスバーの「保存」** です。

### 4.4 uv / git ツール（FastAPI 配置 → 拡張が取得）

**配置場所の正本**: [ツール配布-配置場所.md](./ツール配布-配置場所.md)

サーバに手動配置（例）:

```text
nora-backend\data\tools\uv\0.6.0\uv.exe
nora-backend\data\tools\git\2.54.0\PortableGit-2.54.0-64-bit.7z.exe
```

配置後、manifest の **sha256 / size** を実ファイルに合わせる（プレースホルダ `aaaa…` のままだと拡張側で検証エラー）。

拡張側コマンド:

| コマンド | 用途 |
|----------|------|
| **NoraOps: ツールをセットアップ（uv / git）** | FastAPI から DL → `%LOCALAPPDATA%\NoraOps\runtime\tools\` |
| **NoraOps: ツールの状態を確認** | バージョン・更新要否の表示 |

起動時の **PyGarden 自動セットアップは廃止**（2026-05 以降）。404 が出たらサーバ側のファイル未配置を疑う。

**NoraOps「保存」だけ**なら uv は不要。git は同梱 Portable Git または PATH の `git`。

## 5. 動作確認シナリオ（この順がおすすめ）

### シナリオ A — オフライン最小（サーバ不要）

1. Extension Development Host で**空フォルダ**を開く  
2. `main.py` など適当なファイルを作成  
3. 画面下ステータスバー **「保存」** をクリック  
4. **期待**: ローカルに git commit。サーバが無ければ「オフライン」扱いで push はスキップ

### シナリオ B — オンライン・チェックのみ

1. **2章**の FastAPI を起動  
2. フォルダを開き **保存**  
3. **期待**: サーバのルールでチェック（IP 直書き等で警告が出ることもある）  
4. Output → 拡張ホストのログにエラーが無いこと

### シナリオ C — Gitea へ初回 push（リポ自動作成）

**前提**: FastAPI + Gitea + 拡張設定が揃っている。

1. 新しい空フォルダ `C:\work\my-test-app` を開く  
2. **保存** を 1 回  
3. **期待**  
   - 名前確認ダイアログ（既存名と被る場合）  
   - `nora/manifest.json` 等の雛形ができる  
   - `git remote -v` に `origin` が付く  
   - Gitea に `my-test-app` 相当のリポができる  
4. ホーム（**NoraOps: ホームを開く**）で「クラウドに反映済み」に近い表示

手動確認:

```powershell
cd C:\work\my-test-app
git remote -v
git log -1
```

### シナリオ D — 「新しいアプリ」フロー

1. コマンド **NoraOps: ホームを開く**  
2. **新しいアプリを作る** → フォルダ選択  
3. **期待**: フォルダが開き、remote 設定まで進む（初回保存前でも可）

### シナリオ E — Python 環境（uv・オンデマンド）

**前提**: `pygarden` ツールセットアップで `uv.exe` が入っている（`%LOCALAPPDATA%\PyGardenRuntime\tools\uv\uv.exe`）。

1. `nora/packages/pyproject.toml` があるワークスペースを開く（保存で雛形作成済みでも可）  
2. コマンド **NoraOps: Python 環境を用意する**（またはホームの **Python 環境を用意する**）  
3. **期待**  
   - venv: `%LOCALAPPDATA%\NoraOps\venvs\<16文字ハッシュ>\`  
   - ワークスペース `.nora/python-env.json` にパス記録  
   - `uv sync` 完了の通知  
4. 確認:

```powershell
type .nora\python-env.json
dir $env:LOCALAPPDATA\NoraOps\venvs
```

> ワークスペースごとに venv を分離。不要になった venv フォルダは手動削除で OK（再実行で作り直し）。

### シナリオ F — セキュリティゲート（F5）

1. `main.py` に社内 IP らしき直書き（チェックルールに依存）を入れる  
2. **保存** → 警告は出るが保存は可能（設計どおり）  
3. **F5 デバッグ** → **期待**: オンライン時はセキュリティ NG なら開始ブロック

| 症状 | 確認すること |

| 常にオフライン | FastAPI が起動しているか、`noraops.server.baseUrl` が `127.0.0.1:8000` か |
| push しない | `noraops.save.pushOnSave`、Gitea token、`git remote -v` |
| リポ作成失敗 503 | サーバ `.env` の `GITEA_*`、Gitea が起動しているか |
| リポ作成 409 | 同名リポが既にある → 別名を選ぶ |
| uv / Python 環境エラー | PyGarden セットアップ完了、`nora/packages/pyproject.toml` の有無 |
| `uv.exe` 404 | **4.4** — `scripts\fetch-uv-dev.ps1` で配布物を配置 |
| ホームタブが消えた | **4.3** — 下の **NoraOps** クリック、または「ホームを開く」 |
| `getaddrinfo failed` | Gitea URL が存在しないホスト名になっていないか |

## 10. Runner モードの試し方（Phase1b 薄型）

**記録の正本**: [実装記録.md](./実装記録.md)

### 10.1 サーバ

1. FastAPI を起動（§2 参照）。
2. 開発で一覧を出したいだけなら `.env` に `NORAOPS_CATALOG_DEV_SHOW_ALL=1`（**FastAPI を再起動**）。
3. 本番想定では Gitea リポに topic **`nora-published`** を付与。

**Gitea 403 `read:user`**: `GITEA_LIST_MODE=instance` 時、古いサーバは `/user/repos` で落ちることがある。  
→ コードは `repos/search` だけで続行するよう修正済み。**FastAPI を再起動**すること。  
トークンに **`read:user` を足す**か、組織だけ見るなら `GITEA_LIST_MODE=scoped` + `GITEA_ORGS=あなたの組織名` でも可。
4. 確認用 URL:
   - `GET http://127.0.0.1:8000/api/v1/portal/catalog/published`
   - `GET http://127.0.0.1:8000/api/v1/noraops/client/latest`
   - `data/noraops/client-latest.json` で版・vsix URL を編集可

### 10.2 拡張（F5 の開き方）

**どちらかのフォルダを VS Code / Cursor で開く**

| 開くフォルダ | F5 |
|--------------|-----|
| リポジトリルート | `.vscode/launch.json` の「▶ NoraOps拡張を起動」（あれば） |
| `vscode-extension` のみ | 同フォルダの `.vscode/launch.json` |

F5 後に **もう一つ** VS Code ウィンドウ（**[Extension Development Host]**）が開く。**Runner の UI はこの 2 つ目のウィンドウ**で見る（1 つ目は拡張のソース用）。

**Runner を開く方法（どれか 1 つ）**

1. 画面下ステータスバー **`▶ アプリを使う`**（追加済み）
2. NoraOps ホームの **`アプリを使う（承認済み一覧）`**
3. `Ctrl+Shift+P` → **`NoraOps: アプリを使う（Runner）`**
4. 設定 `noraops.mode` = **`runner`**（起動時に Runner タブが自動で開く）

**注意**: `noraops.mode` が **`auto`**（既定）で **フォルダを開いている** と、起動時は **開発用ホーム**（保存ボタン）だけが出る。Runner の「このアプリを使う」は **Runner 画面を開いたあと**、一覧の各アプリの下に出る。

| 設定 | 意味 |
|------|------|
| `noraops.mode` | `runner` / `creator` / `auto`（フォルダあり→creator） |
| `noraops.runner.autoOpen` | 起動時にホーム／Runner を開く |
| `noraops.client.checkUpdateOnStartup` | `client/latest` と版比較 |

3. Runner 画面で **このアプリを使う** → shallow clone → `uv sync` → detached `uv run`。
4. キャッシュ先: `%LOCALAPPDATA%\NoraOps\runner-apps\`。

**Gitea**: `noraops.gitea.baseUrl` と `noraops.gitea.token`（private リポの clone 用）。
