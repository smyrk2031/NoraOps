# 開発者向けガイド（Creator）

> **注（2026-06）**: ワークスペース構成を [ワークスペース設計改定.md](./ワークスペース設計改定.md) に追随予定（ルート `pyproject.toml` / `assets/`、`.nora` → AppData）。**現行コードは本文のパスで動作** — [互換方針.md](./互換方針.md) 参照。

## どこを編集してよいか

| 場所 | 編集 |
|------|------|
| ルートの `*.py` | ○ 本体コード |
| 独自フォルダ（`src/` 等） | ○ 自由 |
| `README.md` | ○ 利用者向け説明 |
| `nora/packages/pyproject.toml` | △ 依存の追加・変更は OK（name はツールが直す場合あり） |
| `nora/manifest.json` | **× 手編集しない** — 起動ファイル・サムネは Creator の UI から |
| `nora/assets/` | ○ サムネイル画像（Creator で保存） |
| `.nora/` | 拡張のメタ（保存先 Gitea 名など） |

## おすすめレイアウト

```text
my-app/
├── README.md
├── myapp.py          ← 例: main.py ではなくこちらを起動したい
├── nora/             ← NoraOps 管理領域（中身は UI 操作）
│   ├── manifest.json
│   ├── assets/thumbnail.png
│   └── packages/
│       ├── pyproject.toml
│       ├── main.py     ← 雛形の初期エントリ
│       └── .venv/      ← uv の仮想環境（.gitignore 済み）
└── .vscode/launch.json
```

## 開発の流れ

1. **雛形を入れる**（不足ファイルだけ追加）
2. 手動 or **GitHub Copilot** でコード
3. **pyproject** に依存を書く
4. **uv** で `nora/packages/.venv` を作成・同期
5. **F5** でデバッグ
6. **起動 .py を指定**（myapp.py 等）→ **サムネ** → **Gitea 保存**

詳細: [Giteaリポジトリ要件.md](./Giteaリポジトリ要件.md)
