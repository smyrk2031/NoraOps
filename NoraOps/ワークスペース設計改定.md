# NoraOps ワークスペース設計改定（設計正本）

**状態**: 計画中（実装フェーズ別に段階導入）  
**目的**: Creator / Runner を多様なユーザー像に合わせ、**開発リポジトリを汚さず**、**迷わせない** UX を実現する。  
**関連**: [現状とアーキテクチャ.md](./現状とアーキテクチャ.md)（三層 API 構成）／[互換方針.md](./互換方針.md)（旧レイアウト読み取り）

---

## 1. 背景と課題

現行 Creator は **0→1 新規開発（greenfield）** を主眼に `nora/` ツリー（`dev/`, `mock/`, `packages/`）と `.nora/`（session 等）を自動生成する。以下のユーザーには **過剰・邪魔** になりうる。

| 像 | 概要 | 現状の摩擦 |
|----|------|------------|
| **① greenfield** | プロンプトコピペで 0→1 | 現行フローと一致（問題少） |
| **② import** | 既存アプリを Gitea / Runner へ | `nora/dev` 等が不要なのに checklist / scaffold が残る |
| **③ fork** | Runner アプリをカスタム | artifact 由来の `nora/` はそのまま利用可 |
| **④ venv-only** | ポリシー + uv のみ、Gitea 不使用 | scaffold / session が git に近い場所に増える |

**設計原則**

1. **触らないのがデフォルト** — プロファイルに応じ、不足分だけ補う  
2. **Git に載せるのはアプリと公開契約のみ** — PC ローカル状態は AppData  
3. **Python の慣習に合わせる** — ルート `pyproject.toml` + ルート `.venv`  
4. **整合性は裏で、UI は矛盾時だけ** — `giteaRepoId` / `appId` で機械判定  
5. **既存レイアウトは読み取り互換** — 移行はユーザー同意後（[互換方針.md](./互換方針.md)）

## 2. 三層モデル（A / B / C）

ワークスペース上のデータを **3 層** に分離する。

```text
┌─────────────────────────────────────────────────────────┐
│ A. ユーザーのアプリ（Git 正本・レイアウト自由）          │
│    README.md, ソース, pyproject.toml, assets/           │
├─────────────────────────────────────────────────────────┤
│ B. NoraOps 公開契約（Git に載せる・最小）                │
│    nora/manifest.json（+ manifest が参照する assets）   │
├─────────────────────────────────────────────────────────┤
│ C. PC ローカル（AppData・リポ / zip に載せない）         │
│    .venv, 紐づけ, プロファイル, 警告確認, Runner 展開    │
└─────────────────────────────────────────────────────────┘
```

| 層 | 例 | Gitea zip | ユーザ git |
|----|-----|-----------|------------|
| **A** | `main.py`, `src/`, `README.md`, `pyproject.toml` | 含む | 含む |
| **B** | `nora/manifest.json` | 含む | 含む（公開する人のみ） |
| **C** | session, venv meta, `runner-envs/` | **除外** | **除外** |

**廃止方向**

- ワークスペース内 **`.nora/`** → AppData `workspaces/` へ移行  
- **`nora/dev`**, **`nora/mock`** → ① greenfield のみ（オプション scaffold）  
- **`nora/packages/`** → 新規はルート `pyproject.toml`（旧パスは互換読み取り）

## 3. Git 理想形（NoraOps 公開可能アプリ）

Gitea 保存・Runner 配布の **推奨リポジトリ構成**。

```text
my-app/
├── README.md                 # 利用者向け（テンプレ付き・§5）
├── pyproject.toml            # uv 依存の正本（ルート）
├── .gitignore                # .venv, .env, __pycache__ …
├── main.py                   # または src/ …（自由）
├── assets/                   # README 画像 + Runner サムネ
│   ├── thumbnail.png         # Runner カード（推奨）
│   └── screenshot-01.png     # README から参照
├── nora/
│   └── manifest.json         # NoraOps 契約のみ
└── .vscode/
    └── launch.json           # 任意（F5）
```

**zip / git で除外（現行と同趣旨）**

| 除外 | 理由 |
|------|------|
| `.venv/`, `venv/` | `uv sync` で再現 |
| `.git/` | サーバー側 git |
| `.env`, 秘密鍵 | セキュリティ |
| AppData 相当 | ワークスペース外 |

**① greenfield のみ追加（オプション）**

```text
nora/dev/       # AI 生成コード置き場（0→1 補助）
nora/mock/      # UI モック（プロンプト用）
```

## 4. Creator プロファイル

拡張はワークスペースごとに **プロファイル** を AppData に保持する（git に載せない）。

| プロファイル | ID | 自動 scaffold | Gitea | UI |
|-------------|-----|---------------|-------|-----|
| **0→1 新規** | `greenfield` | README テンプレ, assets/, pyproject, manifest, **任意** dev/mock | 任意 | mock / dev / env / cloud |
| **既存公開** | `import` | manifest + 不足分のみ（README, pyproject, assets） | 目的 | env / cloud（mock・dev 非表示） |
| **Runner 派生** | `fork` | artifact 展開先を編集（基本 import 相当） | 任意 | import 寄り |
| **venv + ポリシーのみ** | `venv-only` | **何も作らない** | 使わない | env + ポリシーのみ |

**プロファイル選択**

- 初回: ユーザーが rail で選ぶ（現行 `greenfield` / `import` を拡張）  
- 推測: ルート `pyproject.toml` あり → import 候補、manifest なし + Gitea 未使用 → venv-only 候補（**自動確定しない・提案のみ**）

**scaffold トリガー（改定後）**

| 操作 | greenfield | import | venv-only |
|------|------------|--------|-----------|
| フォルダを開く | 何もしない | 何もしない | 何もしない |
| 「雛形を入れる」 | フル | 最小 | 拒否 / 説明 |
| 「環境を用意する」 | pyproject なければ提案 | 同左 | 既存 pyproject のみ |
| Gitea 保存 | manifest なければ **同意後** 生成 | 同左 | N/A |

## 6. Python 環境

### 6.1 Creator（開発）

| 項目 | 改定後 |
|------|--------|
| `pyproject.toml` | **ワークスペースルート**（既存があればそれを使用） |
| `.venv` | **ワークスペースルート** `.venv/` |
| 記録 | AppData `workspaces/{id}.pythonEnv`（**キャッシュ**。probe で補完） |

**venv 探索順（meta なし時）**

1. `{workspace}/.venv/Scripts/python.exe`（Windows）  
2. AppData に記録された `venvDir`  
3. VS Code `python.defaultInterpreterPath`  

### 6.2 Runner（利用）

Runner は **リポジトリ内 venv を使わない**。すべて AppData。

```text
%LOCALAPPDATA%\NoraOps\
  runner-apps\{owner}\{name}\     # artifact 展開（ソースのみ）
  runner-envs\{owner}\{name}\     # uv sync 先 .venv
```

## 7. AppData レイアウト

```text
%LOCALAPPDATA%\NoraOps\
  runtime\tools\uv\uv.exe          # 固定（既存）
  recent-apps.json                 # 最近開いたアプリ（既存・拡張）
  workspaces\
    {workspaceKey}.json            # ワークスペース状態（新規）
  runner-apps\                     # 既存
  runner-envs\                     # 新規（Runner 専用 venv）
  dev-apps\                        # 既存（ソースを編集）
  venvs\                           # 旧 Runner 用（段階的に runner-envs へ）
```

### 7.1 workspaceKey

```
workspaceKey = sha256(normalize(absoluteWorkspacePath))
```

- パス変更時: `appId` / `giteaRepoId` で **再接続**（矛盾時のみ UI）

### 7.2 workspaces/{key}.json（概要）

スキーマ詳細は実装フェーズ `appdata-01` で [workspaces-schema.md](./workspaces-schema.md) に定義。

| フィールド | 内容 |
|-----------|------|
| `schema` | `nora.workspace/1` |
| `workspacePath` | 最後に開いた絶対パス |
| `creatorProfile` | `greenfield` / `import` / `fork` / `venv-only` |
| `appId` | manifest と同期 |
| `giteaRepoId` | Gitea 数値 ID（安定キー） |
| `giteaFullName` | `owner/name`（キャッシュ・リネーム時更新） |
| `pythonEnv` | venvDir, lastSyncAt, … |
| `securityWarnState` | 確認済み fingerprint |
| `lastSave`, `lastPushOk` | UI 用 |

**移行**: 既存 `.nora/session.json` 等を初回読み込み時に取り込み、以降 AppData のみ書く（`.nora` フォールバック読み取りは互換期間）。

## 8. Gitea 紐づけ

### 8.1 識別子の役割

| ID | 発行元 | 用途 |
|----|--------|------|
| **`appId`** | NoraOps（manifest） | 論理アプリ ID。誤保存防止の正本 |
| **`giteaRepoId`** | Gitea API `id` | 物理リポ。リネーム・パス変更に強い |
| **`owner/name`** | Gitea | API 呼び出し・表示（**キャッシュ**） |

### 8.2 整合性チェック

| タイミング | 処理 |
|-----------|------|
| フォルダ open | `giteaRepoId` で Gitea GET → `full_name` 更新（静かに） |
| 保存前 | manifest `appId` ↔ サーバー registry；保存先 `giteaRepoId` 一致 |
| 矛盾 | モーダル（別 appId / 別リポ） |

### 8.3 サーバー DB（拡張）

`nora_app_registry` に `gitea_repo_id` 列を追加（nullable → 初回 save で埋める）。
