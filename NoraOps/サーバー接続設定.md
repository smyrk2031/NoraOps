# NoraOps サーバー接続設定（拡張 v0.10+）

## 概要

拡張は **Creator / Runner とは別の「NoraOps 設定」タブ** で、バックエンド（FastAPI）への接続を行います。

- ステータスバー: **設定**（歯車）
- コマンド: **NoraOps: 設定（サーバー接続）**

## 何を入力するか

**ブラウザで NoraOps ポータルのトップが表示される URL** をそのまま入力します。

| 環境 | 入力例 |
|------|--------|
| ローカル開発 | `http://127.0.0.1:8000` |
| 社内 IP | `http://192.168.1.50` |
| HTTPS | `https://noraops.contoso.local` |
| IIS + ARR（サブパス） | `https://intranet.example.com/NoraOps` |

拡張は自動で次のように API に接続します:

```text
{入力URL}/api/v1/portal/health
{入力URL}/api/v1/noraops/...
```

末尾の `/` は不要です。誤って `/api/v1/...` まで貼った場合もベース URL に補正します。

## 初回セットアップ手順

1. VS Code に拡張をインストール
2. **NoraOps 設定** タブを開く（初回は自動で開く場合あり）
3. ポータル URL を入力
4. **接続テスト** — 「NoraOps API（ポータル）」が OK になること
5. **保存して適用**
6. 必要なら **uv セットアップ** → **Creator** / **Runner**

## IIS + ARR + uvicorn（本番想定）

```text
ブラウザ  https://win-server/NoraOps
    ↓ IIS (ARR)
    ↓ リライト例: /NoraOps/* → http://127.0.0.1:8000/*
uvicorn  FastAPI  :8000
```

**チェックポイント**

- ブラウザで `https://win-server/NoraOps` が開く（または `/` リダイレクト）
- 同じホストで `https://win-server/NoraOps/api/v1/portal/health` が `{"status":"ok",...}` を返す
- 拡張の接続テストが OK

ARR でパスを削る場合（外部 `/NoraOps/api` → 内部 `/api`）も、**ブラウザで届く URL** を拡張に入力すれば動作します。

## VS Code 設定キー

| キー | 説明 |
|------|------|
| `noraops.server.baseUrl` | 上記ポータル URL（グローバル推奨） |

設定 UI から保存するとこのキーに書き込まれます。

## 社内プロキシ（HTTP_PROXY）

| コンポーネント | 既定の挙動 |
|----------------|------------|
| **nora-backend (httpx)** | `trust_env=False` — 環境変数 `HTTP_PROXY` を**使わない**（Gitea / Azure 直結） |
| **VS Code 拡張** | Node `http.request` — **HTTP_PROXY を使わない** |
| 外向きだけプロキシ必須 | サーバー `.env` で `NORAOPS_HTTP_TRUST_ENV=1`（要検証） |

開発者 PC に `HTTP_PROXY` がある場合、社内 IP の NoraOps サーバーは **NO_PROXY** に入れる運用が一般的です。設定タブの接続テストにプロキシ情報が表示されます。

詳細: [接続の堅健性チェック.md](./接続の堅健性チェック.md)
