# リポジトリ棚卸プラン（Phase 0）

**目的**: 整理作業の前に「何があるか」「何が現行か」を一覧化する。  
**実施**: 別タスク（本書は手順と記録テンプレートのみ）。  
**親プラン**: [リポジトリ整理プラン.md](./リポジトリ整理プラン.md) Phase 0  
**成果物（作業後に作る）**: [docs/inventory.md](../docs/inventory.md)（**2026-06-20 作成済**）

---

## 1. いつ・誰が・どれくらい

| 項目 | 目安 |
|------|------|
| 所要 | 1〜2 日（1 人） |
| コード変更 | 原則なし（一覧 MD の追加・タグ付けのみ） |
| 事前 | git tag 例: `pre-inventory-2026-06` |
| 事後 | `棚卸し一覧.md` 完成 → Phase 1（ドキュメント整流）へ |

---

## 2. 分類ルール（3 + 補助）

棚卸の各行に **主分類** を1つ付ける。

| 主分類 | 意味 | 例 |
|--------|------|-----|
| **実装あり** | コードがあり、現行フローから到達可能 | `serverSave.js`, `POST /repos/save` |
| **ドキュメントのみ** | MD や構想だけ。コードに対応なし or 一部のみ | 旧 `archive/フェーズ進行.md` |
| **廃止候補** | コードは残るが非推奨・参照ほぼなし | `POST /repos/push` (bundle) |

**補助タグ**（ドキュメント用・複数可）:

| タグ | 意味 |
|------|------|
| `現行` | 正本として維持 |
| `要更新` | 実装はあるが MD が古い（版数・API 名） |
| `archive済` | 既に `archive/` にある or 移動予定 |
| `重複` | 別 MD と内容重複。マージ or 片方 archive |
| `別製品` | NoraOps 外（PyGarden 等） |

## 3. 作業手順（0.1 〜 0.5）

### 0.1 — `ver1/` 直下の分類

**やること**

1. 直下のファイル・フォルダを一覧（PowerShell 例）:

```powershell
Get-ChildItem <リポジトリルート> -Force |
  Where-Object { $_.Name -notin @('node_modules','.git') } |
  Select-Object Mode, Name
```

2. 各エントリを次のいずれかに分類して `棚卸し一覧.md` §0.1 に記入:

| 分類 | 想定 |
|------|------|
| **NoraOps 現行** | `vscode-extension/`, `nora-backend/`, `NoraOps/` |
| **NoraOps 凍結** | `portal/` |
| **別製品** | ルート `package.json`, `main.js`, `renderer/`, `node_modules/`（PyGarden） |
| **生成・ローカル** | `nora-backend/data/`, `.pytest_cache/`, `*.vsix` コピー先 等 |
| **要判断** | 上記に当てはまらないもの |

**記録テンプレート（§0.1）**

```markdown
| パス | 分類 | メモ |
|------|------|------|
| vscode-extension/ | NoraOps 現行 | 拡張正本 |
| package.json | 別製品 | PyGarden。NoraOps と無関係 |
```

**やること**

1. ファイルごとに先頭 5 行へメタを追記（棚卸時のみ。Phase 1 で正式化）:

2. 主分類 + 補助タグを表にする。

**初期の仮ラベル（作業前の目安・要確認）**

| ファイル | 仮タグ | 備考 |
|----------|--------|------|
| 現状とアーキテクチャ.md | 現行 | 実装判断の正本 |
| 機能一覧とAPI.md | 現行 | v0.16 済。router 差分は 0.4 で確認 |
| 実装記録.md | 現行 | リリース正本 |
| リポジトリ整理プラン.md | 現行 | 計画のみ |
| 棚卸プラン.md | 現行 | 本書 |
| README.md | 現行 | Phase 1 で目次刷新予定 |
| 今後のUX改善.md | 現行 | バックログ |


### 0.3 — 拡張モジュール ↔ 機能

**対象**: `vscode-extension/src/noraops/*.js`（`runner/` 含む）

**やること**

1. `現状とアーキテクチャ.md` §3 の機能 ID 表をベースに列を追加  
2. 各 `.js` を「主担当」「参照のみ」「未使用候補」に分類  
3. `package.json` の `contributes.commands` と突合（コマンド未登録の js は要確認）

**確認コマンド例**

```powershell
Get-ChildItem vscode-extension\src\noraops -Recurse -Filter *.js |
  Select-Object -ExpandProperty Name
```

**記録テンプレート（§0.3）**

```markdown
| モジュール | 機能ID | 主分類 | package.json command | メモ |
|------------|--------|--------|----------------------|------|
| serverSave.js | F-save | 実装あり | noraops.save | zip 保存正本 |
| gitBundle.js | — | — | — | 存在しないこと確認 |
```

---

### 0.4 — サーバー API ↔ ドキュメント

**対象**: `nora-backend/app/**/routers/*.py` vs `機能一覧とAPI.md`

**やること**

1. router から `@router.get/post` パスを抜き出す（手動 or 簡易 grep）  
2. 機能一覧に **あるがコードにない** / **コードにあるが一覧にない** を2リスト化  
3. `include_router` されていない router ファイルがないか `main.py` で確認

**grep 例**

```powershell
rg "@router\.(get|post|put|delete|patch)\(" nora-backend\app --glob "*.py"
```

**記録テンプレート（§0.4）**

```markdown
### 一覧にのみ（要 MD 削除 or 実装予定）
- ...

### コードにのみ（要 MD 追記 or 廃止候補）
- POST /api/v1/repos/push | 廃止候補 | bundle 非推奨
```

---

### 0.5 — 廃止・凍結候補の集中確認

**チェックリスト**（Yes/No を `棚卸し一覧.md` §0.5 に記入）

| # | 対象 | 確認方法 | 期待 |
|---|------|----------|------|
| 1 | `POST /api/v1/repos/push` | 拡張から grep `repos/push` | 未使用なら廃止候補 |
| 2 | `portal/` | README・import 参照 | 凍結・削除候補 |
| 3 | `serverPush.js` / `gitBundle.js` | 拡張 tree に存在するか | 無いこと |
| 4 | PyGarden ルート | 拡張・サーバーから require されていないか | 無関係 |
| 5 | `NORAOPS_CLIENT_EXPOSE_GITEA_TOKEN=1` | 本番 .env | 使っていない |
| 6 | pypiserver プロセス | 本番 | 未導入なら「任意・未使用」で OK |
| 7 | `data/tools/**` 巨大バイナリ | .gitignore | リポに含める必要の有無 |
