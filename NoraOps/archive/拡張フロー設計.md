# NoraOps VS Code 拡張 — フロー設計（別紙）

[フェーズ進行.md](./フェーズ進行.md) の **VSCode-8〜16** の **中身を細かく書く場所**。実装チケットは **フロー ID**（下記）で分割してよい。

**画面・ボタン・履歴の具体**は **[拡張UI設計.md](./拡張UI設計.md)** を正とする（保存／履歴／リポ名確認／チェックタイミング）。本紙の **ブランチ・PR・マージ**は **上級者プロファイル**用。初心者向け既定は **main 一本・マージ UI なし**（[設計の絞り込み.md](./設計の絞り込み.md)）。

## 設計原則（再掲）

- **非エンジニア／野良アプリエンジニア**が **最初に触っても迷わない**こと最優先。
- **難しい UI は禁止**。常に **今どの段階か・次は何か**が分かる（番号・パンくず・短い説明）。
- **Git を意識させない**：用語は **ゲーム感覚で押せるラベル**に落とし、裏で Git が動く。**気づいたときにはもうバージョン管理できている**状態を目指す。

---

## Git と画面語彙の対応（固定しておく表）

| 画面で見せる言葉（例） | 内部的な意味（Git / Gitea） | 備考 |
|------------------------|------------------------------|------|
| **アプリ名** | **リポジトリ名**（＋オーナー） | 新規時は **FastAPI-15** と整合してからローカルと紐付け |
| **作業名** | **ブランチ名**（例: `feature/<user>_<date>`） | ユーザーには「今の改良」「〇〇の試し」など表示してもよい |
| **セーブ／同期**（明示ボタン） | `git add` + `git commit`（＋必要なら **作業ブランチへの push**） | オートセーブと役割分担（下記ステップ②） |
| **リリース／できた！** | 作業ブランチの **push** + **`main` 向け Pull Request 作成**（＋組織設定なら自動マージ） | **必ず FastAPI-14（Push 前ゲート）を通す**。ここが **不完全 Push 防止**の要 |

**不完全 Push 防止**との関係:

- **リリース（`main` 統合の入口）の直前**に **FastAPI-14** を必須にし、**必須ファイル・ポリシー観点**が揃っているかをサーバ基準で判定する。
- **オートセーブ**は主に **ローカル commit** に留め、**解析に必要なファイルが揃うまで `main` / 承認フローに乗せない**ことで、「空のリポが Gitea に上がって放置される」リスクを下げる。
- **不足があれば VSCode-13** で雛形挿入 or **FastAPI-12** 用のプロンプト案内（AI OFF なら手順のみ）。

## ステップ①：起動・再開（`VSCode-UI-5` / `VSCode-UI-6`）

**正本**: [拡張UI設計.md](./拡張UI設計.md) §10・§11。  
VS Code 起動時は **NoraOps ホームタブ**（WebviewPanel）を開き、大きなボタン中心の HTML を出す。

| ボタン（文言例） | 裏の挙動（概念） | ユーザー体験 |
|------------------|------------------|----------------|
| **「続きから始める」** | `meta.json` → フォルダを開く → `git pull`（main） | 「おかえりなさい」→ 前回のアプリが開く |
| **「新しいアプリを作る」** | FLOW-NEW へ | 名前確認 1 回 → フォルダ／リポ準備 |
| **「別のアプリを開く」** | 最近のアプリ一覧 | Excel の「最近使ったブック」 |

**常設**: 保存・履歴は **ステータスバー**（ホームを閉じていても同じ）。  
旧 `VSCode-14` のブランチゲートウェイは **上級者プロファイル**用に文書のみ残す。

## ステップ②：作業中の「オートセーブ」（`VSCode-15`）

**保存ボタンを別概念にしなくてもよい**設計もあるが、原則は次のとおり。

| トリガ | 裏の挙動 | ユーザー体験 |
|--------|----------|----------------|
| **ファイル保存（Ctrl+S）** または **N 分おき** | `git add -A` + `git commit -m "Auto save: …"`（**push はしない**） | 「フリーズしても数分前には戻れる」安心感。**Git を意識させない**。 |

**任意拡張（別チケット可）**: 「クラウドにバックアップ」ボタンで **作業ブランチのみ `push`**（`main` には触れない）。

**FastAPI-14 との関係**: オートセーブは **ローカル履歴**。**リリース**するときだけゲートを通す。

---

## ステップ③：完了時の「報告／リリース」（`VSCode-16`）

画面右下の **「できた！」** や専用タブの **「公開する」** など、**常に見つかる完了導線**。

| 段階 | 裏の挙動（概念） | ユーザー体験 |
|------|------------------|----------------|
| 1 | **FastAPI-14** 実行 → 不足なら **VSCode-13** で補完してから再実行 | ブロッキングせずチェックリストで案内 |
| 2 | 作業ブランチを **`push`** | 進捗表示 |
| 3 | **Gitea API で `main` 向け Pull Request 作成**（タイトル・本文はテンプレ＋作業名から自動） | 「お疲れ様！レビューに出しました」等 |
| 4 | （**組織が明示的に許可した場合のみ**）自動マージ or 承認者通知 | **既定は自動マージ OFF**（事故防止） |

**演出**: 紙吹雪・短い祝福メッセージなど **ポジティブフィードバック**は許容（オプトアウト可）。

## コンフリクト（必ず別設計で詰める）

**現状**: 本紙では **要件のみ**置く。実装前に RFC を切る。

- **起動ゲート**で `main` を先に取る／作業ブランチ一本化で **発生率を下げる**。
- **リリース直前**に `main` を再取り込み（merge or rebase）し、**競合検出**したら **ビジュアル手順**（「どちらを残すか」）へ誘導。**CLI を見せない**。
- **自動マージ OFF** なら、PR 上で解消してもらう経路も併記。
- **拡張だけで解決できない**場合は Gitea Web UI への **ワンリンク**は出してよい（逃げ道）。

## ルート選択（トップ分岐）

| フロー ID | 名前 | 概要 | 関連 VSCode ID |
|-----------|------|------|-----------------|
| **FLOW-NEW** | 新しくアプリを作る | … → **ゲートウェイ** → … → **FastAPI-14** → **リリース** | VSCode-8, 10, 12〜16, FastAPI-14, 15 |
| **FLOW-IMPROVE** | 既存アプリを直す | **ゲートウェイ** or 省略 → … → **リリース** | VSCode-8, 10, 13〜16, FastAPI-14 |
| （将来）**FLOW-RUN** | 承認済みアプリを使うだけ | カタログ → 実行 | VSCode-3, Client-2 |

各ルートで **やることリスト**を出す（[フェーズ進行.md](./フェーズ進行.md) VSCode-8）。

## FLOW-NEW — ステップ案（追記用）

1. 作りたいことの一言  
2. 類似リポのレコメンド（任意）  
3. テンプレ／言語  
4. **uv** 仮想環境  
5. ローカル動作確認  
6. **FastAPI-15** で新規リポ or 既存接続  
7. **FastAPI-14** + **VSCode-13**（不足時）  
8. 日々の作業：**VSCode-15**（オートセーブ）  
9. **VSCode-16**（リリース）  

※ 画面モック・文言・エラー時の戻り道は追記していく。

---

## FLOW-IMPROVE — ステップ案

1. リポを開く／クローン  
2. **VSCode-14**（任意：続きから）  
3. uv 同期  
4. 作業・**VSCode-15**  
5. **VSCode-13**＋**FastAPI-14**（不足時は補完）  
6. **VSCode-16**

## Gitea 操作を FastAPI に寄せる（動線メモ）

- **新規リポ**: **`FastAPI-15`** に組織名・可視性等を渡し Gitea API → 返却 **clone URL** で `remote` 設定。
- **Push 前**: **`FastAPI-14`** にパス一覧等を送り必須ファイルを検証（全文アップロードは避ける方向）。
- **Push 本体**: ローカル `git`（拡張がラップ）。**リリース**ではその後 **Gitea API で PR**（`VSCode-16`）。

詳細は [責務と境界.md](./責務と境界.md) §1b。

## ワンプッシュ（`VSCode-11`）と `VSCode-16` の役割分担案

| ID | 役割 |
|----|------|
| **VSCode-11** | **開発中**の「この内容をリモートの作業ブランチに載せる」等、**汎用ワンクリック**（上級者・例外パスも含む） |
