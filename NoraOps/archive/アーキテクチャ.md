# NoraOps アーキテクチャ

前提の整理は [前提と全体像.md](./前提と全体像.md)。ここでは **技術構成** に絞る。

## 1. 論理構成（4 本柱）

```
                    ┌─────────────────────────────────────┐
                    │ ② NoraOps API（FastAPI）             │
                    │ ・解析（SEC/LICENSE/類似）            │
                    │ ・承認ゲート／公開カタログ            │
                    │ ・ダッシュボード・JSON API           │
                    │ ・配布ページ HTML（.vsix 案内）       │
                    └──────────────┬──────────────────────┘
                                   │ HTTPS
       ┌───────────────────────────┼───────────────────────────┐
       │                           │                           │
       ▼                           ▼                           ▼
┌─────────────────────┐   ┌───────────────┐           ┌───────────────┐
│ ③ VS Code 拡張       │   │ Tauri（将来）  │           │ ブラウザのみ   │
│ Creator + Runner    │   │ Runner のみ    │           │ （運用者閲覧） │
└──────────┬──────────┘   └───────┬───────┘           └───────────────┘
           └──────────────┬────────┘
                      │ Git + HTTP API
                      ▼
             ┌─────────────────┐
             │ ① Gitea         │
             │ Repo / Release  │
             └─────────────────┘

        （任意・将来） Azure OpenAI ← ② の AI ゲートウェイのみ
```

## 2. データの権威（Single source of truth）

| 種類 | 権威の置き場 | ② FastAPI の役割 |
|------|----------------|------------------|
| ソース・タグ・Release | **① Gitea** | キャッシュ・解析結果・サマリ |
| **ユーザー向け「公開」の可否** | **② の承認レコード（DB）** | ゲートのみ。Runner は **`published`** 経由のみ |
| アプリ実行マニフェスト | リポ内＋ Release asset | ルール提示・テレメトリ |
| セキュリティ／ライセンス／類似度スコア | **② DB**（再計算可） | バッチ・オン要求 |
| uv / Git バイナリ | **② 配布ストレージ** + manifest | checksum 付き配信（拡張・将来 Tauri が取得） |

## 3. Git ホスト抽象化（Gitea 優先）

| メソッド（概念） | Gitea | GitHub（将来） |
|------------------|-------|----------------|
| `listRepositories` | search / org / user API | 同等 |
| `getRelease` | Releases API | Releases API |
| `createPullRequest` 等 | API 差分をアダプタで吸収 |

**初手**: `GiteaProvider` のみ実装。[責務と境界.md](./責務と境界.md) と [API設計.md](./API設計.md) の `/api/v1/git/...` を参照。

## 4. FastAPI（②）のレイヤ

| レイヤ | 責任 |
|--------|------|
| **公開 Web** | トップ：**クライアント／.vsix のダウンロード or リンク**、簡単なオンボーディング |
| **HTTP / 認証** | API Key 等 |
| **Git プロバイダ** | ① へのアクセス |
| **解析** | メタのみ → 必要に応じ clone / tarball ジョブ |
| **ルール** | セキュリティ・ライセンス・命名 |
| **AI ゲートウェイ** | フラグ・レート・ログ（任意） |

## 5. クライアント（拡張 + 将来 Tauri）のレイヤ

| モード / 製品 | 責任 |
|---------------|------|
| **Creator**（拡張） | 開発・保存・Gitea・チェック・エディタ診断 |
| **Runner**（拡張内 / 将来 Tauri） | 承認済みカタログ、疎取得、**uv で venv・実行** |
| **Tauri**（将来） | Runner と同 API。IDE なし |

共有：tools manifest、`%LOCALAPPDATA%\NoraOps\runtime`（[ポータルとクライアント.md](./ポータルとクライアント.md) · [配布検討.md](./配布検討.md) B）。

## 6. 配置パターン（参考）

| 規模 | 典型 |
|------|------|
| 個人・小チーム | ①② 同居 or 別プロセス、`sqlite` |
| 部門 | ② `postgres`、① は別サーバ |
