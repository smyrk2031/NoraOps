# NoraOps4code — 拡張 UI 設計（優先）

**対象読者**: 実装者・デザインレビュー。**Pydev（社内 PyPI ミラー）は後回し**（[フェーズ進行.md](./フェーズ進行.md) `FastAPI-16` は Phase2 以降）。

**思想**: ユーザーは **VS Code と（あれば）GitHub Copilot** だけで開発する。**Git・差分・マージ・コンフリクトは画面に出さない**。  
**コード全体を何度も「保存」**することで、裏の Git が履歴を積み、**プラットフォームのチェック**が自然なタイミングで入る。

関連: [設計の絞り込み.md](./設計の絞り込み.md)（main 一本）／[拡張フロー設計.md](./拡張フロー設計.md)（フロー ID）／[フェーズ進行.md](./フェーズ進行.md)（機能 ID）／**[チェック仕様.md](./チェック仕様.md)**（セキュリティ全文・`/nora/` ポリシー・実行割り込み）

## 1. 二層 UI（「怖くない部屋」＋「いつでも触れる操作」）

非エンジニア向けに、**操作は常に同じ場所**、**説明・安心は専用の部屋**に分ける。

```text
┌─ VS Code 全体 ─────────────────────────────────────────────┐
│  [ エディタタブ: app.py ] [ NoraOps ホーム ★ ]  …          │  ← 専用タブ（開いておいてよい）
│  ┌──────────┬──────────────────────────────────────────┐  │
│  │ NoraOps  │  コード編集（Copilot 等はそのまま）          │  │
│  │ サイド   │                                              │  │
│  │ [ホーム] │                                              │  │
│  │ [履歴]   │                                              │  │
│  │ [チェック]│                                              │  │
│  └──────────┴──────────────────────────────────────────┘  │
│  [ NoraOps ] ●未保存 | [保存] [履歴] | 最終14:32 | 要修正2  │  ← 常設（タブを閉じても残る）
└────────────────────────────────────────────────────────────┘
```

| 層 | 名前 | VS Code API | いつ見えるか |
|----|------|-------------|--------------|
| **常設クローム** | 操作バー | `StatusBarItem`（左・複数） | **常に**（エディタタブ・サイドバーを閉じても） |
| **専用ホーム** | NoraOps の部屋 | `WebviewPanel`（エディタ列の **1 タブ**）＋ `WebviewView`（サイド） | 初回起動・再開時に **自動で 1 回開く**（以降はユーザーが閉じても可） |
| **モーダル** | 名前確認など | `QuickInput` / 限定的な `showInformationMessage` | 初回・エラー時のみ |

### 1.0 設計原則（この章の芯）

| 原則 | 内容 |
|------|------|
| **保存・履歴はタブに依存しない** | Python ファイルを見ていても、ホームを閉じていても、**ステータスバーは同じ** |
| **何かあったら 3 秒で分かる** | 色＋短い日本語（要修正・クラウド済・未送信）。詳細はホーム／チェックタブ |
| **ホームは「説明と安心」** | コードはエディタ、NoraOps は **いまどうなってる？次は？** |
| **Git 用語は出さない** | Gitea には「クラウド」「アプリの名前」 |

### 1.1 常設クローム（ステータスバー）— 最優先実装

**どのタブを開いていても同じ位置・同じラベル。**

| 要素 | 役割 |
|------|------|
| `[ NoraOps ]` | クリックで **ホームタブ**を開く（無ければ作成） |
| 状態インジケータ | Excel 風（§1.2） |
| `[ 保存 ]` `[ 履歴 ]` | 主操作。履歴はサイドの履歴ビューを前面化 |
| 最終保存時刻 | `最終保存 14:32` |
| 段階（任意） | `お試し開発` — クリックで変更 |

**実行（F5）ボタンはステータスバーに置かない**（VS Code 標準の実行を使うが、セキュリティ NG 時はゲートで止める）。

### 1.2 ステータスバー レイアウト（案）

```text
[ NoraOps ]  ● 未保存の変更  |  [ 保存 ]  [ 履歴 ]  |  最終保存 14:32  |  （チェック ✓）
     ^              ^              ^           ^              ^                ^
  ブランド      状態インジケータ   主操作      副操作        Excel風タイムスタンプ   軽い結果
```

| 表示 | 意味（ユーザー向け） | 裏（実装メモ） |
|------|----------------------|----------------|
| `● 未保存の変更` | エディタに未反映の変更あり | `workspace.isDirty` |
| `✓ 保存済み・クラウド済` | commit + push 成功、チェック OK | 理想状態 |
| `✓ 保存済み（要修正 2）` | push 済みだが **セキュリティ NG** | **実行不可**。クリックで直し方 |
| `✓ 保存済み（整理推奨 1）` | push 済み、ポリシーのみ未達 | 実行可。雛形サジェスト |
| `☁ クラウド未送信` | commit 済み、push 失敗 | [ 再送 ] |
| `… チェック中` | スキャン中 | — |
| `段階: お試し開発` | `nora/manifest.json` の `stage` | ドロップダウンで変更 |

**色**: VS Code のテーマに追従（`ThemeColor`）。未保存＝琥珀、`要確認`＝赤系だが **威圧的なアラート連打はしない**。

## 2. 保存の UX（Excel っぽく、簡単に）

### 2.1 「保存」1 ボタンの挙動

ユーザーが **保存**を押す（または `Ctrl+S`）たびに、**常に同じパイプライン**を走らせる（段階が増えても画面は増やさない）。

```text
1. エディタ内容をディスクへ
2. セキュリティ／ポリシーをチェック（結果だけ記録・保存は止めない）
3. git commit（ローカル履歴）
4. git push → Gitea（既定 ON）
5. ステータス更新（未達なら「要修正」「整理推奨」を明示）
```

詳細は **[チェック仕様.md](./チェック仕様.md)** §4・§8。

| 設定 | 既定 | 説明 |
|------|------|------|
| 保存のたび Gitea に送る | **ON** | ローカル＋クラウドを常に近づける |
| チェック未達でも push | **ON** | バックアップ優先。未達は UI で明示 |
| セキュリティ NG 時の実行 | **常に不可** | F5・実行ボタンはハードブロック |
| ポリシー NG 時の実行 | **可** | 構造不足だけでは止めない |
| 開発の段階 | `trial` 初期値 | お試し／本番／完成／VerUP（manifest + 任意 tag） |

**Excel との対応**

| Excel | NoraOps4code |
|-------|----------------|
| 保存マーク（●） | `● 未保存の変更` |
| 最終保存時刻 | `最終保存 14:32` |
| 名前を付けて保存 | **初回のみ**リポ名確認（§3） |
| 履歴（共同編集） | **履歴**パネル（§5） |

### 2.2 Gitea への push（保存に含める）

**既定**: 保存＝ローカル commit ＋ **Gitea へ push**（main）。別ボタンは不要。  
push 失敗時だけ「クラウド未送信」＋再送。オフラインではローカルのみと表示。

**開発の段階**（お試し／本番／完成／バージョンアップ中）はステータスバーまたはサイドバーで選択。  
裏では `nora/manifest.json` の `stage` と、必要時のみ **Git tag**（[チェック仕様.md](./チェック仕様.md) §8）。

## 3. リポジトリがまだないとき（フォルダ名 → 自動作成）

### 3.1 トリガ

次のいずれかで **リポ作成フロー**を開始する。

- フォルダを開いたが **`.git` なし**
- **初めて保存**したとき
- サイドバー NoraOps の **「このフォルダをアプリとして登録」**（任意）

### 3.2 名前の決め方（聞くのは最小限）

1. **候補名** = ワークスペースフォルダ名を **スラッグ化**（例: `請求ツール v2` → `seikyu-tool-v2`）
2. **Quick Pick 1 画面だけ**:

```text
タイトル: アプリの名前
本文:   この名前で保存の履歴をクラウドに残します。
        変えたい場合だけ編集してください。

[  seikyu-tool-v2          ]  ← 入力欄（既定＝候補）
[ この名前で始める ]  [ あとで ]
```

- **聞かないもの**: オーナー、可視性、ブランチ、`.gitignore` の中身（すべて裏で既定）
- **聞くもの**: 名前だけ（デフォルト箱の名前を差し替えるか、の一点）

### 3.3 重複チェック（必須・しっかり）

**作成前に必ず**サーバ経由で Gitea 上の同名を検索する（[フェーズ進行.md](./フェーズ進行.md) `FastAPI-15` ＋ 検索 API）。

| 結果 | UI |
|------|-----|
| **同名なし** | そのまま `FastAPI-15` でリポ作成 → ローカル `git init` + `remote` + 初回 commit |
| **同名あり** | モーダルで停止。既存の **表示名・最終更新・オーナー**を 1 行で見せる。「別の名前を付ける」だけ選択肢（マージ・上書きは **不可**） |
| **通信失敗** | 「今は名前を確認できません。オフラインでは新規作成できません」— **誤って被せない** |

```text
⚠ 同じ名前のアプリがすでにあります

  「seikyu-tool-v2」  最終更新: 2025-11-03  担当: 山田

  別の名前を付けないと、上書きしてしまう恐れがあるため
  作成を中止しました。

  [ 名前を変えて再試行 ]
```

**ローカル側の二重チェック**: `meta.json` の `appId` / `remoteUrl` が既に別フォルダに紐づいていないかも見る。

### 3.4 作成後

- `.gitignore` をテンプレから自動生成（更新のみ、編集 UI は出さない）
- ステータスバー: `✓ 保存済み` ＋ サイドバーに **「アプリ: seikyu-tool-v2」**（小さく）
- 初回保存版を履歴に **「はじめての版」** と表示

## 4. チェック（セキュリティ全文 ＋ リポジトリポリシー）

**正本**: [チェック仕様.md](./チェック仕様.md)

### 4.1 セキュリティ（`VSCode-SEC-1`）

| 検出例 | 保存 | 実行（F5） |
|--------|------|------------|
| IP・パスワード・シークレット等 | **可**（要修正表示） | **不可** |

| タイミング | 挙動 |
|------------|------|
| **保存** | スキャン → **commit + push は続行** → 「要修正 N」とサジェスト |
| **実行・デバッグ（F5 等）** | **セキュリティ NG なら必ずキャンセル** |

ルールは `vscode-extension/resources/checks/security.rules.json`（**後から JSON で追加可**）。

### 4.2 リポジトリポリシー（`VSCode-POL-1`）

| 必須 | 内容 |
|------|------|
| トップ | `README.md` または `README.html` |
| `nora/manifest.json` | アプリ ID・表示名など |
| `nora/packages/` | `pyproject.toml`（＋推奨 `uv.lock`）で uv 復元 |
| `.gitignore` | 無ければ **自動生成**（重い拡張子・`.env` 等） |

**ポリシー未達でも保存・push 可**。サイドバー「チェック」で **[ 雛形を入れる ]** と **Copilot への聞き方**を出す。

### 4.3 クラウドに送る前（追加）

サーバ `FastAPI-14` で LICENSE 等を再確認（ローカルと **同じ ruleId** を共有）。

## 5. 履歴 UI（バージョン切り戻し）

### 5.1 入口

- ステータスバー **「履歴」**
- コマンドパレット `NoraOps: 履歴を開く`（補助）

### 5.2 一覧（Webview・サイドバー）

**時系列（新しい順）**。1 行 = 1 版。

| 列（表示） | 内容 |
|------------|------|
| 時刻 | `2026/05/18 14:32` |
| 種別 | `保存` / `自動保存` / `クラウドに送った` |
| ラベル | 自動: `作業中の版`、手動: ユーザーが付けられる短いメモ（任意） |
| 状態 | `この PC` / `クラウドにもある` |

**操作（各行）**

| ボタン | ユーザー向け説明 | 裏 |
|--------|------------------|-----|
| **この版を見る** | 読み取り専用で中身を確認 | `git show` + 一時ディレクトリ or 差分なしファイル一覧 |
| **この版に戻す** | 今の作業をこの時点に戻す | `git checkout` 相当（**main 一本**、[設計の絞り込み.md](./設計の絞り込み.md)） |
| **名前を付ける** | あとで探しやすいラベル | `git tag` 相当だが画面では **「お気に入りの版」** |

### 5.3 「この版に戻す」の確認（コンフリクトを見せない）

```text
14:32 の版に戻しますか？

  いまの変更は、戻す前に自動で 1 版保存されます。
  （元に戻したいときは履歴から選べます）

  [ 戻す ]  [ やめる ]
```

- 戻す前に **必ず現在状態を auto-commit**（安全網）
- リモートより古い版に戻したあと **クラウドに送る**ときは、組織ポリシーで **force 禁止**なら「新しい版として送る」経路のみ（詳細は実装 RFC）

### 5.4 履歴の見た目（ワイヤー）

```text
┌─ NoraOps ─────────────────────────┐
│ [ 履歴 ] [ チェック ] [ このアプリ ] │
├───────────────────────────────────┤
│ 今日                              │
│  ● 14:32  保存        この PC      │ [見る] [戻す]
│  ○ 14:28  自動保存    この PC      │
│  ☁ 12:00  クラウドに送った  共有済  │ [見る] [戻す]
│ 昨日                              │
│  ○ …                              │
└───────────────────────────────────┘
```

**diff ビューは既定 OFF**。上級者設定で「変更したファイル数」だけ見せてもよい。

## 7. Copilot との共存

| 方針 | 内容 |
|------|------|
| インストール | 初回セットアップ manifest の **推奨**（失敗しても NoraOps は動作） |
| チェック | Copilot 生成直後はスキャンしない。**保存後**に走らせてノイズ低減 |
| 修正 | セキュリティ指摘は **行を開く**まで。Copilot Chat への自動投稿はしない |

## 10. 専用タブ「NoraOps ホーム」（載せる情報のたたき台）

**まだ全部は決めなくてよい。** Phase1 は **大きいボタン＋いまの状態**だけでも、非エンジニアはかなり怖くなくなる。

### 10.1 開き方

| タイミング | 挙動 |
|------------|------|
| VS Code 起動（NoraOps 有効） | **ホームタブを 1 枚開く**（既に開いていれば再利用） |
| ステータスバー `[ NoraOps ]` クリック | 同上 |
| コマンド `NoraOps: ホームを開く` | 同上 |

実装: `WebviewPanel.createWebviewPanel` で **エディタ領域のタブ**（サイドだけだと見落とされやすいため **両方**用意。内容は同期）。

### 10.2 ホーム画面のブロック（優先度付き）

| 優先 | ブロック | 載せる情報（案） | なぜ |
|------|----------|------------------|------|
| **P0** | **いまのアプリ** | 表示名、段階（お試し等）、最終保存、クラウド（Gitea）同期状態 | 「ちゃんと預かれている」安心 |
| **P0** | **次にやること 1 行** | 例: 「保存を押すとクラウドに残ります」／「要修正 2 → 直し方を見る」 | 迷子防止 |
| **P0** | **大ボタン** | `前回の続き` / `別のアプリを開く` / `新しいアプリ` | 再開の入口 |
| **P1** | **チェックサマリ** | セキュリティ要修正件数、ポリシー整理推奨、**[ 直し方 ]** | ホームからでも気づける |
| **P1** | **直近の履歴 3 件** | 時刻・種別・**[ 戻す ]** | 履歴タブを開かなくても十分なこと多い |
| **P2** | **はじめての人向け** | 3 ステップ図（編集→保存→クラウド済） | 初日だけ表示、折りたたみ可 |
| **P2** | **Copilot のヒント** | 「聞き方をコピー」リンク | ポリシー未達時だけ |
| **Runner** | カタログ・承認済みアプリ実行 | **Runner モード専用 Webview** | Creator ホームと分離 |

**あえて載せない（ホームに）**: ファイルツリー、ターミナル、Git ログ、diff。

### 10.3 サイドバーとの役割分担

| ビュー | 内容 |
|--------|------|
| **ホーム**（タブ＋サイド先頭） | 挨拶・状態・大ボタン・次の 1 手 |
| **履歴** | 全件・版戻し・ラベル |
| **チェック** | ルール別の詳細・雛形・Copilot 聞き方 |

ステータスバーの **[ 履歴 ]** は **履歴ビュー**を開く。**ホームは閉じたままでよい。**

### 10.4 ワイヤー（ホーム・P0 のみ）

```text
┌─ NoraOps ホーム ──────────────────────────────────────┐
│  請求ツール（お試し開発）                                │
│  ✓ 14:32 保存済み · クラウド（Gitea）にも反映済み        │
│  ⚠ 実行前に 2 か所直すと安全です  [ 直し方を見る ]       │
│                                                        │
│  ┌──────────────────┐  ┌──────────────────┐          │
│  │  前回の続き      │  │  別のアプリを開く  │          │
│  └──────────────────┘  └──────────────────┘          │
│  ┌──────────────────┐                                  │
│  │  新しいアプリ    │                                  │
│  └──────────────────┘                                  │
│                                                        │
│  次: コードを直したら、下の「保存」を押してください      │
│      （どの画面でも右下にあります）                      │
└────────────────────────────────────────────────────────┘
```

## 11. すべて閉じたあと — 自然な再開発（再開フロー）

**ゴール**: Excel で「ブックを閉じて、来月また開く」感覚。  
**データの手がかり**: `%LOCALAPPDATA%/NoraOps/apps/{appId}/meta.json` ＋ Gitea 上の最新。

### 11.1 トリガ

| 状況 | 挙動 |
|------|------|

| 前回のワークスペースを VS Code が復元 | 通常編集＋ステータスバー更新。ホームは **開かない**（設定で ON 可） |

### 11.2 再開画面（ホームの初期モード）


| ボタン | 裏 |

| **最近のアプリ** | ローカル `meta.json` 一覧（最大 5）。無ければ Gitea「自分が触ったリポ」から補完（Phase2） |
| **新しいアプリ** | FLOW-NEW へ |

### 11.3 「続きから」の細かい手順（ユーザーには見せない）

1. ローカルフォルダが無い → **Gitea から clone**（appId / リポ名で）  
2. ローカルがある → **pull** でクラウドの最新を取る  
3. `nora/manifest.json` の `stage` をステータスバーに反映  
4. チェックを 1 回走らせ、ホームに **要修正があれば表示**（保存は既にクラウドにあるので責めない）  
5. 1 行メッセージ: **「続きからできます。編集して保存を押してください。」**
