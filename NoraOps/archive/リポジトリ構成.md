# NoraOps リポジトリ構成（実装の置き場所）

**3 コンポーネント**で正しい。物理フォルダは次のとおり（既存名は活かし、中身を NoraOps 化していく）。

```text
ver1/
├── vscode-extension/          … ① NoraOps4code（VS Code 拡張）
├── softrail-server/           … ② FastAPI（サーバ。名称は後で noraops-server へ可）
├── portal/                    … スケルトンのみ（実装は vscode-extension Runner へ）
├── NoraOps/                   … 設計ドキュメントのみ（コードは置かない）
└── README.md                  … 全体の入口
```

## ② FastAPI の中身（論理モジュール）

`softrail-server/app/noraops/` に **連携ごと**に分ける（マイクロサービス分割は後回し）。

| サブフォルダ | 連携 | Phase |
|--------------|------|-------|
| `routers/checks.py` | 拡張・チェックルール `GET /api/v1/checks/rules` | **1a** |
| `routers/repos.py` | Gitea プロキシ・編集リース（将来） | 1a' / 1b |
| `routers/portal_api.py` | 公開カタログ等 JSON（**拡張 Runner + 将来 Tauri**） | 1b |
| `routers/ai.py` | 組織 OpenAI・ログ（既定 OFF） | 2 |
| `routers/pydev.py` | 社内 PyPI ミラー（将来） | 2+ |
| `services/` | ルール読込・lease ストア等 | — |

レガシー `app/routers/catalog.py` 等は **残す**（互換）。新規は `noraops` 名前空間。

## ① 拡張の中身

```text
vscode-extension/src/noraops/     … NoraOps 本体
  activate.js, statusBar.js, savePipeline.js  … Creator（Phase1a）
  toolInstaller.js, toolsPaths.js               … 共有ツール（uv/git）
  runner/                                     … Runner（Phase1b・旧ポータル相当）
vscode-extension/resources/checks/ … ルール JSON（オフライン用）
```

`extension.js` は **noraops のみ**起動（PyGarden 自動 bootstrap は廃止）。

## ③ ポータル（方針）

- **Phase1b〜**: 機能は `vscode-extension` の **Runner モード**（Webview + 同 API）
- **`portal/`**: 新規実装しない。将来 Tauri は別フォルダ想定
- 正本: [ポータルとクライアント.md](./ポータルとクライアント.md)
