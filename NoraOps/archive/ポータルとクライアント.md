# ポータルとクライアント（方針・2026）

**決定**: 旧「クライアントポータル」（PySide6 / Electron モック）の機能は **基本的に VS Code 拡張に統合**する。  
**将来**: 軽量環境を望む利用者向けに **Tauri 専用クライアント**を別途用意する（同じ FastAPI API）。

関連: [拡張UI設計.md](./拡張UI設計.md) · [配布検討.md](./配布検討.md) · [リポジトリ構成.md](./リポジトリ構成.md)

---

## 1. なぜ見直したか

| 以前 | いま |
|------|------|
| ③ 別デスクトップポータル（PySide6 等） | **③ は VS Code 拡張内の Runner モード** |
| ④ VS Code 拡張は「作る人」中心 | **① Creator + ② Runner の 2 モード** |
| uv / git / Gitea 連携が二重実装になりそう | **正本は FastAPI `data/tools` + 共有 API** |

PyGarden 名義の Electron ポータルは **別プロダクトのモック**であり、NoraOps では **実装しない**。

---

## 2. クライアントの二段構成

```text
                    [ FastAPI ]
                    カタログ / 承認 / ツール manifest / ルール / .vsix 案内
                         ↑ 同じ HTTP API
           ┌─────────────┴─────────────┐
           │                           │
   [ VS Code + NoraOps4code ]    [ Tauri クライアント（将来）]
   ・配布の正（Phase1）          ・軽量・IDE なし向け（Phase2+）
   ・Creator モード              ・Runner のみ
   ・Runner モード（ポータル相当）
```

| モード / 製品 | 誰向け | 典型操作 |
|---------------|--------|----------|
| **Creator**（拡張） | アプリを **作る** 人 | 編集 → 保存 → Gitea、チェック、再開 |
| **Runner**（拡張内） | アプリを **使う** 人（コードしない） | 承認済みカタログ → uv で取得・実行 |
| **Tauri クライアント**（将来） | VS Code を **避けたい** 人 | Runner と同 API・同 UX 目標 |

---

## 3. VS Code 拡張に載せるポータル機能（Runner）

Phase1b 以降、拡張側に **`noraops.mode`: `creator` | `runner`**（案）で切り替え。

| 機能（旧 Client-*） | 拡張での置き場（案） |
|---------------------|----------------------|
| 承認済みカタログ検索 | Runner 用 Webview（ホームとは別タブ or モード専用ホーム） |
| 疎取得 + uv 実行 | 既存 `toolInstaller` + detached `uv run` |
| テレメトリ | 既存 FastAPI `telemetry`（`source: extension` / `runner`） |

**Creator ホームに載せない**（[拡張UI設計.md](./拡張UI設計.md) §10）: カタログ・他人アプリの実行は Runner に集約。

### Runner の UX 方針（非エンジニア）

- VS Code 起動時に **ポータル相当の Webview を前面**（ワークスペース推奨 settings で UI ノイズ低減）
- Python 起動は **detached プロセス** — 案内で「起動後 VS Code を閉じてもアプリは動き続ける」可能性を示す
- **IT 入門**として「フォルダ・保存・クラウド」の次に「社内アプリを起動」まで一つの道具で説明できる

## 4. 将来: Tauri 軽量クライアント

| 項目 | 方針 |
|------|------|
| **目的** | VS Code の重量（RAM・更新・IDE ノイズ）を避けたい部門向け |
| **時期** | Runner の API と UX が **拡張で固まってから**（Phase2+） |
| **技術** | **Tauri** 想定（Electron は重量のため採用しない） |
| **共有** | FastAPI の `portal_api` / 公開カタログ / tools manifest — **拡張と同じ契約** |
| **配布** | 薄い exe + 社内コード署名。uv/git は同じ `%LOCALAPPDATA%\NoraOps\runtime` でもよい |

実装開始の条件例:

- 拡張 Runner で Client-1/2 相当が動いている
- 「VS Code 必須が難しい」部門が具体的にいる
- HTTP クライアント層の API 契約が文書化されている（[API設計.md](./API設計.md)）

## 5. リポジトリ上の扱い

| パス | 扱い |
|------|------|
| `vscode-extension/src/noraops/` | **Creator**（現状）+ **runner/**（将来） |
| `portal/` | **スケルトンのみ・新規実装はしない**。Tauri 開始時に `client/tauri/` 等へ移す想定 |
| `softrail-server/app/noraops/routers/portal_api.py` | **共有 API** — 拡張 Runner と将来 Tauri の両方から利用 |

## 6. 配布・OTA

| 対象 | 配布 |
|------|------|
| **主経路** | VS Code + `.vsix`（全員インストール） |
| **ルール・ツール** | FastAPI のみ更新（拡張再配布不要） |
| **拡張本体** | `.vsix` 再配布 + 将来 `GET /api/v1/noraops/client/latest` で更新通知 |
| **Tauri** | 別チャネル（将来） |

詳細: [配布検討.md](./配布検討.md) · [NoraOpsの導入.md](./NoraOpsの導入.md)

---

## 7. コード整理（事故防止）

| 原則 | 内容 |
|------|------|
| **フォルダ分離** | `creator/` · `runner/` · `tools/` · `core/` |
| **機能フラグ** | 未成熟 Runner は既定 OFF |
| **API 契約固定** | `/api/v1/...` — Tauri も同じ |
| **PyGarden 残滓** | カタログ用 legacy は触らず、NoraOps からは呼ばない |

## 8. フェーズ対応（抜粋）

| Phase | 内容 |
|-------|------|
| **1a** | Creator のみ（保存・Gitea・ツール・ルール） |
| **1b** | 拡張 Runner 薄型（カタログ + uv run）、`portal_api` スタブ拡張 |
| **2+** | 承認 UI（Web 中心）、Tauri クライアント検討 |

機能 ID の詳細: [フェーズ進行.md](./フェーズ進行.md)（Client-* は **実装先 = 拡張 Runner / 将来 Tauri** と読み替え）
