# NoraOps4code — チェック仕様（セキュリティ／リポジトリポリシー）

[拡張UI設計.md](./拡張UI設計.md) の補足。**ルールは後から増やせる**ことを最優先に設計する。

| チェック | ID（チケット） | 保存 | 実行（F5 等） |
|----------|----------------|------|----------------|
| **セキュリティ（全文）** | **VSCode-SEC-1** | **可**（NG を明示＋直し方サジェスト） | **不可**（情報流出リスク） |
| **リポジトリポリシー** | **VSCode-POL-1** | **可**（同上） | **可**（構造不足だけでは実行は止めない） |

**原則**: **保存は止めない**。チェック未達でも履歴に残し **Gitea へ push してよい**。  
**オンライン時**はセキュリティ NG で実行禁止。**オフライン時**は閉じた環境のため実行ゲートを **緩和**（§1.3）。

## 1. 共通アーキテクチャ

### 1.1 ルールエンジン（拡張内）

```text
ルール定義（JSON / YAML）
    ↓ マージ
組織ルール（FastAPI から取得・任意）
    ↓ マージ
リポジトリ上 nora/policy.local.json（任意・上書きは禁止項目のみ）
    ↓
CheckRunner.run(context) → CheckResult[]
```

| 項目 | 説明 |
|------|------|
| **CheckResult** | `ruleId`, `severity`（`error` \| `warn`）, `message`, `file`, `line`, `column`, `snippet`, `fixActions[]` |
| **error**（セキュリティ） | **実行をブロック**。保存は可だが UI を **「要修正」** |
| **error**（ポリシー） | 保存・実行とも **ブロックしない**。サジェスト必須 |
| **warn** | 保存可。ステータスバー `⚠`、サイドバーに表示 |

**ルール追加** = 運営は **FastAPI の rules JSON** に 1 エントリ追加（`custom` 種別だけ拡張再配布が必要）。

### 1.3 オンライン / オフライン

| 状態 | ルール取得 | push | セキュリティ実行ブロック |
|------|------------|------|--------------------------|
| オンライン | API → 失敗時同梱 | 試行 | **あり** |
| オフライン | 同梱のみ | **スキップ**（「この PC のみ」） | **なし**（流出リスク低とみなす） |

### 1.2 ルール定義の置き場所（優先順）— FastAPI-17

**同期ではなく、同じ契約のルール束を配る**（[スリムPhase1.md](./スリムPhase1.md) §5）。

| 順 | パス | 用途 |
|----|------|------|
| 1 | 拡張同梱 `resources/checks/*.rules.json` | **オフライン・初回のフォールバック** |
| 2 | **`GET /api/v1/checks/rules`**（`etag` / `If-None-Match`） | **運営が更新する正本**（オンライン時） |
| 3 | ワークスペース `.nora/policy.override.json` | Phase1b 以降（warn→error の昇格のみ） |

将来の FastAPI 横断静的解析（FastAPI-4〜6 本格化）も **同じ `ruleId`・同じ JSON** をサーバ内で使う。

## 2. セキュリティチェック（全文）

### 2.1 目的

**IP 直書き**、**パスワード**、**アカウント名**、**シークレットキー**などを  
ワークスペース内の **テキストとして全文スキャン**し、検出したら **実行前に必ず止める**。保存時は **結果を見せるだけ**（保存自体は止めない）。

### 2.2 既定ルール一覧（`ruleId`）

| ruleId | 検出内容 | 既定 severity | 備考 |
|--------|----------|---------------|------|
| `sec.ip_literal` | IPv4 / IPv6 リテラル（`127.0.0.1` 等） | error | `0.0.0.0` / localhost は **allowlist** で除外可 |
| `sec.password_assignment` | `password`, `passwd`, `pwd` の代入・Dict キー | error | `password=""` も NG |
| `sec.account_name` | `username`, `user_id`, `account` 等への **固定文字列**代入 | warn→error 化可 | 組織で厳格化 |
| `sec.secret_key` | `secret`, `api_key`, `apikey`, `token`, `private_key` 等 | error | |
| `sec.aws_key` | `AKIA…` 形式 | error | |
| `sec.generic_credential` | `Bearer ` + 長い英数字 等 | error | |
| `sec.pem_inline` | `BEGIN PRIVATE KEY` | error | |
| `sec.env_committed` | `.env` 本体が追跡対象（git 追跡 or 存在＋ignore 漏れ） | error | `.gitignore` 自動修正と連携 |

**除外**

- `nora/`, `node_modules/`, `.venv/`, `dist/`, `__pycache__/` 等（glob）
- バイナリ・画像
- `*.md` 内の **例示**は `# noraops:ignore-next-line` コメントで 1 行除外（上級者）

### 2.3 スキャン対象

| 対象 | 含む | 含まない |
|------|------|----------|
| ディスク上のファイル | ワークスペース相対、`.gitignore` 尊重後も **セキュリティは開いたファイル＋ソース系拡張子を重点** | 巨大ファイル（例: >2MB）はスキップ＋ warn |
| 未保存バッファ | **エディタ上の未保存内容を優先**（ディスクより新しい） | |

### 2.4 実行を割り込むタイミング（必須）

**「押された瞬間」に先にチェック → NG ならキャンセル**。

| トリガ | 実装方針（VS Code） |
|--------|---------------------|
| **デバッグ開始**（F5 等） | `DebugConfigurationProvider.resolveDebugConfiguration` で `sec` 実行 → NG なら `null` 返却＋メッセージ |
| **Python: ファイル実行** | `python.execInTerminal` 等を **NoraOps ラップコマンド**に寄せ、`menus` で上書き（NoraOps 有効時） |
| **ターミナルからの run** | 完全捕捉は困難 → **README に「NoraOps の実行ボタンを使う」**＋ 主要コマンドのみラップ |
| **Jupyter / Notebook セル** | Phase2: `notebook.cell.execute` フック検討。Phase1 は **警告** |
| **NoraOps「試しに動かす」** | 自前コマンドで必ずゲート |

```text
ユーザーが [実行] / F5
        ↓
  CheckRunner(context=run)
        ↓
   error あり? ──Yes──► モーダル「安全のため実行を止めました」＋一覧＋[行を開く]
        │
        No
        ↓
   元の実行を続行
```

### 2.5 保存との関係（保存は止めない）

| 方針 | 内容 |
|------|------|
| **セキュリティ error あり** | **保存・commit・push は続行可** |
| **UI** | ステータス **「保存済み（要修正 2）」** — 未達が一目で分かる |
| **サジェスト** | チェックタブに **直し方**＋**Copilot への聞き方**＋**[ 行を開く ]** |
| **Ctrl+S** | ディスク保存は **常に許可**。その後チェック→結果表示→commit→push |

ユーザー向け文言例（保存**後**に表示）:

```text
保存しました（Gitea にも送りました）

  ⚠ 実行する前に直した方が安全な所が 2 か所あります。
  このまま F5 しても動かしません。

  [ 1 か所目を開く ]  [ 直し方を見る ]
```

**理由**: 作業を失わせない。未修正でも **クラウドバックアップ**は価値がある。  
**実行だけ**が漏洩経路なのでそこだけ硬くする。

## 3. リポジトリポリシーチェック

### 3.1 `/nora/` の役割

NoraOps が **「このリポジトリは何か」** を機械的に判断するための **公式メタ領域**。  
アプリ本体コードは従来どおりルート配下でよい。**Python 依存の正本は `nora/packages/`** に集約する。

### 3.2 ディレクトリ構成（契約）

```text
（リポジトリルート）
├── README.md          # または README.html（どちらか必須）
├── .gitignore         # 無ければ拡張が自動生成・更新
├── …（アプリ本体）
└── nora/
    ├── manifest.json       # 必須：リポ identity
    ├── policy.json         # 任意：このリポだけの表示名・言語等
    └── packages/
        ├── pyproject.toml  # 推奨（uv 標準）
        └── uv.lock         # 推奨（復元の再現性）
```

#### `nora/manifest.json`（必須）

```json
{
  "schema": "nora.manifest/1",
  "appId": "nora.app.seikyu-tool-v2",
  "displayName": "請求ツール",
  "language": "python",
  "entry": "main.py",
  "stage": "trial",
  "createdBy": "noraops4code",
  "noraopsVersion": "1"
}
```

`stage` の取りうる値（画面では日本語ラベル）:

| 値 | 画面ラベル | 用途の目安 |
|----|------------|------------|
| `trial` | **お試し開発** | 動くか試している段階 |
| `production` | **本番開発** | ちゃんと作り込んでいる |
| `released` | **完成** | 運用・配布してよい版 |
| `upgrade` | **バージョンアップ中** | 既存完成版を直している |

※ Git の **tag** と併用（§8）。ユーザーには **「段階」** とだけ見せる。

#### `nora/policy.json`（任意）

```json
{
  "schema": "nora.policy/1",
  "readme": { "require": "md_or_html" },
  "packages": { "manager": "uv" }
}
```

#### `nora/packages/`

| ファイル | 役割 |
|----------|------|
| `pyproject.toml` | Python バージョン・依存宣言（**uv の正本**） |
| `uv.lock` | ロック。無い場合は **warn**（保存は可）／組織設定で **error** 化可 |
| `python-version` または `.python-version` | 任意。`pyproject.toml` の `requires-python` があれば不要 |

**uv 復元コマンド（裏）**: `uv sync --project nora/packages`（パスは manifest から解決）。

### 3.3 トップ階層 README

| ルール | 内容 |
|--------|------|
| `pol.readme_exists` | ルートに `README.md` **または** `README.html` |
| 内容 | Phase1 は **存在のみ**。空でも可（warn「説明を書くと喜ばれます」） |

### 3.4 `.gitignore` 自動生成

| 項目 | 内容 |
|------|------|
| トリガ | リポ作成時、ポリシーチェック前、`nora/` 雛形投入時 |
| テンプレ | Python / Node / OS 汎用をマージ |
| 重いファイル | `*.zip`, `*.7z`, `*.iso`, `*.dmg`, `*.exe`（配布物）, `*.parquet`, 動画拡張子 等 |
| 秘密 | `.env`, `*.pem`, `credentials*.json`, `nora/local/`（将来・ローカル専用） |
| 編集 UI | **出さない**。不足パターンはサーバ／拡張更新で追加入り |

### 3.5 ポリシールール一覧（既定 `ruleId`）

| ruleId | 条件 | 既定 |
|--------|------|------|
| `pol.readme_exists` | README.md or README.html | error |
| `pol.nora_manifest` | `nora/manifest.json` があり schema 妥当 | error |
| `pol.nora_packages_pyproject` | `nora/packages/pyproject.toml` | error |
| `pol.nora_packages_lock` | `nora/packages/uv.lock` | warn |
| `pol.gitignore_exists` | `.gitignore` 存在 | error（無ければ **自動生成してから再判定**） |
| `pol.gitignore_covers_env` | `.env` が ignore されている | error（自動追記可） |

**サーバ側**（FastAPI-4〜6）と **同じ ruleId** を共有すると、ローカル保存ゲートとクラウド解析で矛盾しない。

### 3.6 未達時のサジェスト（保存は止めない）

**ポリシー未達でも保存・push はする**。サイドバー **「チェック」タブ**で **「こうすれば OK」** を出す。

```text
いまの保存版は Gitea にあります（要整理 2）

  ☐ README.md（説明ファイル）
      [ 雛形を入れる ]
      💬 Copilot への聞き方:
         「このアプリ用の README.md を初心者向けに書いて。
          機能は〇〇です。」

  ☐ nora フォルダ（NoraOps 用の設定）
      [ まとめて作る ]   ← manifest + packages/pyproject 雛形

  ☐ Python パッケージ設定（nora/packages）
      [ 雛形を入れる ]
      💬 「pyproject.toml で Python 3.11 と fastapi を使う設定を書いて」
```

| ボタン | 動作 |
|--------|------|
| **雛形を入れる** | テンプレートファイルを生成（既存は上書きしない） |
| **まとめて作る** | `nora/` ツリー一式＋ README 最小＋ `.gitignore` |
| **Copilot への聞き方** | クリップボードコピー（Chat は開かない。ユーザーが貼る） |
| **生成 AI（サーバ）** | FastAPI-12 ON の導入社のみ **[ AI に依頼 ]**（Phase2） |

## 4. 保存パイプライン（保存＋Gitea push が既定）

```text
[ 保存 ] / Ctrl+S
    │
    ├─► 1. ディスクへ書き込み
    │
    ├─► 2. セキュリティ全文スキャン → 結果を記録（止めない）
    │
    ├─► 3. リポジトリポリシーチェック
    │         .gitignore 無し → 自動生成 → 再チェック（結果だけ更新）
    │
    ├─► 4. git commit（ローカル履歴）
    │
    ├─► 5. git push origin main（既定 ON）→ Gitea
    │         失敗時: 「保存済み・クラウド未送信」表示＋再試行
    │
    └─► 6. ステータス更新
              チェック OK  → 「✓ 保存済み・クラウド済」
              セキュリティ NG → 「✓ 保存済み（要修正 2）・実行不可」
              ポリシーのみ NG → 「✓ 保存済み（整理推奨 1）」
```

| 設定 | 既定 | 説明 |
|------|------|------|
| 保存のたび Gitea に送る | **ON** | `push` を保存とセット。オフライン時はローカルのみ＋あとで同期 |
| チェック未達でも push | **ON** | バックアップ優先。運用側は Gitea 上の **段階（stage）** で見分け |

**ローカルだけに留めない理由**: PC 故障・別 PC 再開・数か月後の続きのため、**Gitea を常に最新に近づける**。

## 8. 開発の段階（お試し／本番／完成／VerUP）— tag でできるか

**結論: できる。** 裏では Git の **tag**（必要なら Gitea **Release**）を使う。画面では **「段階」** または **「版のラベル」** とだけ表示する。

### 8.1 二層で持つ（おすすめ）

| 層 | 置き場 | 誰が見るか |
|----|--------|------------|
| **いまの作業モード** | `nora/manifest.json` の `stage` | 拡張ステータスバー・毎回の save で更新可 |
| **節目のスナップショット** | **Git tag**（＋任意で Gitea Release） | 履歴パネル「お気に入りの版」 |

### 8.2 画面（ステータスバー or サイドバー）

```text
段階: [ お試し開発 ▼ ]
```

変更すると:

1. `nora/manifest.json` の `stage` を更新  
2. 次の **保存** の commit メッセージに `[お試し]` 等を付与（検索用）  
3. （任意）ユーザーが **「この版にラベルを付ける」** と選んだときだけ **tag を 1 個**打つ  

### 8.3 裏の tag 命名（自動・ユーザーは見なくてよい）

| stage | tag 例（lightweight） | Gitea Release |
|-------|----------------------|---------------|
| `trial` | `nora/stage/trial-20260518-1432` | 通常は作らない |
| `production` | `nora/stage/prod-…` | 任意 |
| `released` | `v1.0.0` または `nora/release/1.0.0` | **推奨**（ポータル承認の入口） |
| `upgrade` | `nora/stage/upgrade-…` | 任意 |

- **main 一本**のまま、tag は **付箋**（その commit を指すだけ）。マージ不要。  
- **「完成」にしたとき**だけ、ウィザードで **バージョン番号**（`1.0.0`）を聞き、`v1.0.0` tag ＋ Release 下書きまで作る（Phase2 でも可）。

### 8.4 履歴パネルでの見え方

```text
14:32  保存   お試し開発   クラウド済   [見る] [戻す] [ラベルを付ける]
12:00  保存   本番開発     クラウド済
```

「ラベルを付ける」＝裏で `git tag`（**版のしおり**）。

### 8.5 FastAPI／ポータルとの関係

- 解析・承認は **`released` 段階の tag** を主に参照すると運用が楽。  
- `trial` の push は **全部 Gitea にあってよい**が、公開カタログには **出さない**（既存の承認フロー）。

## 5. ルール定義ファイル形式（拡張子 `.rules.json`）

```json
{
  "schema": "nora.rules/1",
  "rules": [
    {
      "id": "sec.password_assignment",
      "kind": "regex",
      "pattern": "(?i)(password|passwd|pwd)\\s*[=:]\\s*['\"][^'\"]+['\"]",
      "severity": "error",
      "message": "パスワードの直書きは禁止です。環境変数か設定ファイル（.env は Git に載せない）を使ってください。",
      "globs": ["**/*.py", "**/*.js", "**/*.ts", "**/*.json", "**/*.yaml", "**/*.yml"],
      "excludeGlobs": ["**/nora/**/*.example.*", "**/tests/**"]
    }
  ]
}
```

| `kind` | 用途 |
|--------|------|
| `regex` | 行単位正規表現 |
| `file_exists` | ポリシー用 |
| `file_not_tracked` | `.env` 追跡検出 |
| `custom` | コード内プラグイン（`sec.ip_literal` 等） |

## 6. フェーズ進行 ID 対応

| ID | 内容 | Phase |
|----|------|-------|
| **VSCode-SEC-1** | 全文セキュリティ＋**実行ゲートのみ**（保存は可・要修正表示） | Phase1 |
| **VSCode-POL-1** | `/nora/` 契約・README・ignore 自動・サジェスト（保存可） | Phase1 |
| **VSCode-UI-4** | 開発の段階（stage）＋任意 tag／Release | Phase1（薄く） |
| **VSCode-4** | サーバ連携・禁止コードポリシー拡張 | Phase2 |
| **FastAPI-14** | サーバ側同一 ruleId の検証 | Phase1 |

## 7. Phase1 完了定義（チェックだけ）

1. `password="xxx"` があっても **保存＋push は成功**し、ステータスが **「要修正・実行不可」** と分かる  
2. 同状態で F5 → **実行が始まらない**  
3. ポリシー未達でも保存可。チェックタブで **雛形／Copilot 聞き方**が出る  
4. 保存のたび **Gitea に push**（オフライン時はローカルのみ表示）  
5. **段階**（お試し等）を選べ、`manifest.json` と履歴に反映される  
6. ルール JSON 追加で新 regex が動く
