# バックアップと復元

NoraOps サーバー（FastAPI）と Gitea の **初回セットアップ後の定期バックアップ**、**切り戻し**、**部分復元**の運用ガイドです。

関連: [NoraOpsの導入.md](./NoraOpsの導入.md) · [サーバー接続設定.md](./サーバー接続設定.md) · 管理画面 `/admin/backup`

---

## 1. 何をバックアップしているか

NoraOps **独自のバックアップ機能**（Gitea 標準のバックアップコマンドは使いません）。  
`gitea.exe` のパスを管理画面に登録し、**ファイルコピー + DB ダンプ**で ZIP にまとめます。

| コンポーネント ID | 内容 | 既定 |
|------------------|------|------|
| `backend.db` | **バックエンド DB**（ユーザ・認証・app_config 等） | ✅ |
| `backend.noraops_core` | checks / MCP / prompts / concierge 等 | ✅ |
| `gitea.config` | `app.ini` | ✅ |
| `gitea.db` | Gitea の DB | ✅ |
| `gitea.repos` | リポジトリ実体（`repository.ROOT` 以下） | ✅ |
| `backend.artifacts` | Runner 成果物 | ❌（大容量） |
| `backend.tools` | 配布ツール | ❌（大容量） |

### バックエンド DB の形式

| 設定 | ZIP 内のパス | 方式 |
|------|-------------|------|
| **SQLite**（既定） | `backend/softrail.db` | SQLite `backup()` で整合コピー |
| **Postgres**（`SOFTRAIL_DB_BACKEND=postgres` または `SOFTRAIL_DB_URL`） | `backend/softrail.sql` | `pg_dump`（`--clean --if-exists`） |

ユーザ情報（`noraops_users`・認証トークン・メール紐づけ等）は **すべて `backend.db` に含まれます**。

### Gitea のバックアップの仕組み

Gitea に「バックアップ API を叩いている」わけではありません。

1. 管理画面 **接続設定** で登録した `gitea.exe` から `app.ini` を読む
2. `app.ini` の `[database]` / `[repository]` を解析
3. DB が SQLite なら `gitea.db` をコピー、Postgres なら `pg_dump` → `gitea.sql`
4. リポジトリ ROOT 以下を ZIP に追加

**前提**: サーバーに `pg_dump` / `psql` が PATH にあること（Postgres 利用時）。

## 2. 初回セットアップ時にやること

### 2.1 バックエンド DB

**小規模・単一ホスト（推奨）**

```env
SOFTRAIL_DB_BACKEND=sqlite
SOFTRAIL_SQLITE_PATH=./data/softrail.db
```

**Postgres を使う場合**

```env
SOFTRAIL_DB_BACKEND=postgres
SOFTRAIL_DB_URL=postgresql+psycopg://user:pass@127.0.0.1:5432/noraops
```

DB は初回起動時に `create_all` + マイグレーションで作成されます。

### 2.2 Gitea パス登録（バックアップに必須）

1. 管理画面 → **接続設定**（`/admin/settings`）
2. `gitea_exe_path` に `gitea.exe` のフルパスを保存
3. `/admin/backup` で警告「Gitea パス未検出」が消えることを確認

### 2.3 バックアップ設定（`.env`）

```env
NORAOPS_BACKUP_ENABLED=1
NORAOPS_BACKUP_INTERVAL_HOURS=24
NORAOPS_BACKUP_RETENTION=3
NORAOPS_BACKUP_LOCAL_DIR=./data/backups
# 任意: UNC などへコピー
# NORAOPS_BACKUP_REMOTE_DIR=\\fileserver\share\noraops-backups
# 任意: ZIP を AES 暗号化（持ち出し対策）
# NORAOPS_BACKUP_ZIP_PASSWORD=your-secret
```

### 2.4 初回手動バックアップ

1. `/admin/backup` を開く
2. **今すぐバックアップ** を実行
3. `data/backups/noraops-backup-*.zip` と横の `.manifest.json` ができることを確認

---

## 3. 自動バックアップのルール

| 項目 | 既定 | 説明 |
|------|------|------|
| 有効 | ON | `NORAOPS_BACKUP_ENABLED` |
| 間隔 | 24 時間 | 前回成功から `INTERVAL_HOURS` 経過で実行 |
| 保持 | 3 世代 | 古い ZIP は自動削除（ローカル・リモート両方） |
| 起動時 | スケジューラ登録 | uvicorn 起動と同時にバックグラウンドループ |

手動実行・切り戻し前の pre-restore も同じ `create_backup` を使います。

## 4. 復元の操作（GUI が正本）

**ファイルを手で差し替える運用は不要**です。管理画面から API 経由で上書きします。

### 4.1 画面

| 操作 | 場所 | 確認入力 |
|------|------|----------|
| 一覧・設定 | `/admin/backup` | — |
| 全コンポーネント切り戻し | **切り戻し** | `RESTORE` |
| 一部だけ復元 | **部分復元** | `EXTRACT` + コンポーネント選択 |

### 4.2 API

| メソッド | パス |
|---------|------|
| GET | `/api/admin/backup/status` |
| POST | `/api/admin/backup/run` |
| POST | `/api/admin/backup/settings` |
| POST | `/api/admin/backup/restore` |
| POST | `/api/admin/backup/extract` |
| GET | `/api/admin/backup/{backup_id}/manifest` |

### 4.3 切り戻し時の挙動

1. **pre-restore バックアップ**を自動作成（現在状態の保険）
2. ZIP から選択コンポーネントを展開・上書き
3. SQLite: 既存 `softrail.db` は `.db.pre-restore` にリネーム保存
4. Postgres: `psql -f softrail.sql`（または Gitea 用 SQL）を実行
5. 完了メッセージと warnings を表示

### 4.4 復元後の必須作業

| 復元したもの | 推奨 |
|-------------|------|
| バックエンド DB | **NoraOps サーバー（uvicorn）再起動** |
| Gitea DB / リポ | **Gitea サービス再起動** |
| `app.ini` | Gitea 再起動 |

Postgres 復元中は DB への接続が競合しないよう、可能ならサービスを止めてから実行してください。

## 5. ZIP の中身（参考）

```text
noraops-backup-YYYYMMDD-HHMMSS-xxxxxx.zip
├── manifest.json
├── backend/
│   ├── softrail.db          … SQLite 時
│   ├── softrail.sql         … Postgres 時
│   └── noraops/...          … checks 等
└── gitea/
    ├── custom/conf/app.ini
    ├── data/gitea.db        … Gitea SQLite 時
    ├── data/gitea.sql       … Gitea Postgres 時
    └── repositories/...
```

`NORAOPS_BACKUP_ZIP_PASSWORD` 設定時は ZIP 全体が AES 暗号化されます。7-Zip 等でも開けますが、**管理画面からの復元にはサーバー `.env` に同じパスワード**が必要です。

---

## 6. バックアップに含まれないもの

| 対象 | 理由 |
|------|------|
| `.env` | 秘密情報。別途パスワード管理・インフラの秘密保管 |
| `NORAOPS_USER_TOKEN_SECRET` / `GITEA_TOKEN` | 上に同じ |
| 拡張の AccessToken | クライアント側 SecretStorage |

災害復旧用に `.env` の控えは **セキュアな場所**に保管してください。

---

## 7. トラブルシュート

| 症状 | 確認 |
|------|------|
| Gitea がバックアップに入らない | `/admin/settings` の `gitea_exe_path` |
| Postgres で backend が空 | `pg_dump` が PATH にあるか、`SOFTRAIL_DB_URL` が正しいか |
| 復元後にログインできない | サーバー再起動、バックアップ世代が正しいか |
| ZIP が開けない | `NORAOPS_BACKUP_ZIP_PASSWORD` の一致 |
| SQLite ↔ Postgres のバックアップをそのまま復元できない | 形式が違うため警告のみ。移行は別途 |
