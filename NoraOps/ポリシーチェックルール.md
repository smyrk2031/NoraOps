# ポリシーチェックルールの追加方法

拡張は FastAPI からルール JSON を取得し、**ワークスペース全体を走査**して違反を表示します（保存前の「やること」カード）。

## ルールの置き場所（サーバー）

| ファイル | 種類 |
|----------|------|
| `nora-backend/data/noraops/checks/security.rules.json` | 秘密情報・**IP 直書き禁止**（`sec.ip_literal`） |
| `nora-backend/data/noraops/checks/repo-policy.rules.json` | 構成（README、manifest、pyproject 等） |

API: `GET /api/v1/checks/rules` → 両方をまとめた bundle。

**ポータル CMS**（`/admin/cms`）から上記 JSON を編集・保存すると、即座に API に反映されます（拡張は etag で再取得）。

## ルールを追加する手順

1. 上記 JSON の `rules` 配列にオブジェクトを 1 件追加
2. **FastAPI を再起動**（メモリキャッシュがある場合は `rules_loader` の cache_clear または再起動）
3. VS Code でフォルダを開き直すか、保存チェックを再実行

### 例（repo-policy に追加）

```json
{
  "id": "pol.custom_license",
  "kind": "file_exists",
  "paths": ["LICENSE"],
  "severity": "warn",
  "message": "LICENSE ファイルがあると公開時に安心です。"
}
```

## 主な `kind`（実装済み）

| kind | 意味 |
|------|------|
| `file_exists` | 指定パスが存在 |
| `file_exists_any` | いずれか存在 |
| `gitignore_covers` | .gitignore がパターンをカバー |
| （security 側） | パス・拡張子・正規表現で秘密検出 |

新しい `kind` を足すには `vscode-extension/src/noraops/checkRunner.js` とサーバー側の評価（あれば）の両方が必要です。

## 自動修正 `fixAction`

| fixAction | 動作 |
|-----------|------|
| `auto_gitignore` | テンプレ .gitignore |
| `scaffold_nora` | 雛形（manifest 等） |
| `template_readme` | README 追加 |

Creator の「やること」から **自動修正** ボタンで実行できるものがあります。
