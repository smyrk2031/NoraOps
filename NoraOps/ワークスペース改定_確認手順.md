## 1. 自動で確認できるもの（拡張 UI）

### 1.1 Setting タブ — 接続テスト

1. VS Code で NoraOps を開く → 上部 **Setting**（環境設定）
2. ポータル URL を入力 → **接続テスト**
3. 次が **○** になること:
   - NoraOps API（ポータル）
   - チェックルール
   - ランタイム設定（Gitea 等）
   - Runner カタログ
   - **アプリ紐づけ API**（Phase 4 — registry lookup）

サーバー未起動の場合はここで止まる。FastAPI を起動してから再テスト。

### 1.2 Creator — 動作確認（ヘルスチェック）

1. アプリフォルダを VS Code で開く
2. コマンドパレット → **`NoraOps: 動作確認`**（または Creator ホーム「その他」→ 状態確認系）
3. 横に開く Markdown レポートで確認:
   - サーバー系（従来どおり）
   - **アプリ紐づけ API**
   - **[ワークスペース] pyproject.toml（ルート優先）**
   - **[ワークスペース] Creator プロファイル**
   - **[ワークスペース] giteaRepoId 整合**（保存済みアプリ）

フォルダ未オープン時はワークスペース項目は「スキップ」表示。

### 1.3 開発者向け — npm test / pytest

```powershell
cd vscode-extension
npm test
# → 53+ pass（scaffoldProfile, giteaRepoId, devPrompts, projectPaths 等）

cd ..\nora-backend
python -m pytest tests/test_app_registry_service.py -q
# → gitea_repo_id 列・registry 5 件
```

## 2. 手動確認（プロファイル別）

各シナリオは **別フォルダ** を用意すると混ざりません。

### 2.1 ① greenfield（0→1）

| 手順 | 期待 |
|------|------|
| 空フォルダを開く → rail **0→1** | mock / dev / env / 保存 が有効 |
| 「新しいアプリ」または雛形作成 | `nora/dev`, `nora/mock`, **ルート `pyproject.toml`**, `nora/manifest.json` |
| manifest の entry | `nora/dev/main.py` |
| 環境タブ → プロンプト | 文言が **`pyproject.toml`（ルート）** を指す |
| Python 環境を用意 | **ルート `.venv`** ができる |
| 保存 | Gitea provision → **giteaRepoId** が AppData に記録 |

**AppData 確認**: `%LOCALAPPDATA%\NoraOps\workspaces\{hash}.json` に `giteaRepoId`, `creatorProfile: greenfield`

### 2.2 ② import（既存公開）

| 手順 | 期待 |
|------|------|
| 既存 Python アプリフォルダを開く → rail **公開** | mock / dev **無効**、env / 保存 有効 |
| import ウィザード | entry が `main.py` 等（固定 `nora/dev/main.py` ではない） |
| pyproject 未作成 → 雛形 | **ルート `pyproject.toml`** のみ（dev/mock なし） |
| requirements.txt 指定 → プロンプト | 出力先が **`pyproject.toml`** と表示 |
| 保存 | manifest entry + ルート pyproject で push OK |

### 2.3 ④ venv-only（環境のみ）

| 手順 | 期待 |
|------|------|
| フォルダを開く → rail **環境** | mock / dev / **保存** 無効 |
| 「雛形を入れる」 | **何も作らない**（メッセージで明示） |
| 環境タブ | uv / ポリシーチェックは利用可 |

### 2.4 旧レイアウト互換（読取のみ）

| 手順 | 期待 |
|------|------|
| `nora/packages/pyproject.toml` のみある旧リポを開く | 環境・保存が動く（書込はルート優先） |
| `.nora/session.json` のみある PC | 初回 open で AppData に lazy import |

## 3. giteaRepoId（Phase 4）の手動確認

1. **初回 provision / save 後**  
   - AppData session に `giteaRepoId`（数値）  
   - サーバー DB `nora_app_registry.gitea_repo_id` が埋まる  

2. **API 直接**（ブラウザ or curl）  
   ```http
   GET {server}/api/v1/noraops/apps/binding?gitea_repo_id=42
   GET {server}/api/v1/noraops/apps/binding?app_id=nora.app.xxxx
   ```  
   → `giteaRepoId`, `fullName` が返る  

3. **リネーム耐性（任意）**  
   - Gitea でリポ名変更 → フォルダを開き直す  
   - 静かに `giteaFullName` が更新（矛盾時のみ UI）  

4. **矛盾テスト（任意・上級）**  
   - manifest の appId と別アプリの保存先が混在 → 保存時にモーダルでブロック
