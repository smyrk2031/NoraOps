# NoraOps 縦通し体験手順（開発・デモ用）

**目的**: Creator（作る）→ 保存・Gitea → Runner（使う）までを一度に確認する。  
**記録**: 実装の増減は [実装記録.md](./実装記録.md) に追記。

---

## できること / まだ手動のこと

| ステップ | 状態 | 補足 |
|----------|------|------|
| 空フォルダでアプリ開始 | ○ | 「新しいアプリ」または既存空リポを開く + 保存で雛形 |
| Copilot 等でコード生成 | **手動** | VS Code / Cursor の AI 拡張をそのまま利用 |
| `requirements.txt` | ○ | 雛形あり。`pyproject.toml` が正本（uv） |
| `requirements.txt` 同期 | ○ | コマンド「requirements.txt を pyproject から更新」 |
| uv 環境 + インタプリタ | ○ | 「Python 環境を用意する」→ `python.setInterpreter` |
| F5 で実行 | ○ | 雛形の `.vscode/launch.json`（Python 拡張要） |
| 保存 → Gitea | ○ | **サーバー経由 push**（`git bundle` → `POST /api/v1/repos/push`）。拡張に PAT 不要 |
| Runner 公開（topic） | ○ | push 成功後 `POST /api/v1/repos/publish` |
| Runner で起動 | ○ | 「アプリを使う」→ clone → uv → 起動 |
| 別リポへ「移行」保存 | △ | 新規リポは初回のみ。別リポへの付け替えは未実装 |

## 0. 事前準備（1 回）

### ソフト

| もの | 用途 |
|------|------|
| Gitea（`gitea.exe` 等） | `http://127.0.0.1:3000` |
| FastAPI | `nora-backend` |
| VS Code / Cursor | 拡張 F5 |
| **Python 拡張**（ms-python） | F5・インタプリタ |

### Gitea トークン（ユーザー発行）

**読み取り**（Runner カタログ）に加え、保存・公開には **書き込み** が必要です。

| スコープ | 設定 |
|----------|------|
| **user** | 読み取りと書き込み（リポ新規作成） |
| **repository** | 読み取りと書き込み（サーバー push・topic） |

### FastAPI `.env`（例）

```env
GITEA_BASE_URL=http://127.0.0.1:3000
GITEA_TOKEN=（上記 PAT）
GITEA_LIST_MODE=instance
NORAOPS_CATALOG_DEV_SHOW_ALL=1
```

開発中は `DEV_SHOW_ALL=1` で topic なしでも Runner に出ます。本番確認時は `0` + topic `nora-published`。

### 拡張の設定（Extension Development Host 側）

| 設定 | 例 |
|------|-----|
| `noraops.server.baseUrl` | `http://127.0.0.1:8000`（必須） |
| `noraops.gitea.token` | **空でよい**（v0.4.0〜） |
| `noraops.gitea.defaultOwner` | Gitea のユーザー名（任意） |
| `noraops.mode` | `creator`（開発中はフォルダを開いた状態） |

**サーバー**: ホストに `git` が PATH にあること。

ツール: コマンド「**ツールをセットアップ（uv / git）**」を一度実行。

## 2. Creator：空からアプリ開発

### 2.1 ワークスペースを用意

**どちらか**

- **A**: ホーム →「**新しいアプリを作る**」→ 空フォルダを指定（雛形が入る）
- **B**: 空の Git リポ `test01` を「フォルダを開く」→ コマンド「**アプリの雛形を用意する**」

雛形で入るもの（無いものだけ追加）:

- `nora/packages/pyproject.toml`
- `nora/packages/main.py`（Hello サンプル）
- `nora/packages/requirements.txt`
- `nora/manifest.json`
- `.vscode/launch.json`（F5 用）

### 2.2 AI で編集（手動）

- `main.py` を Copilot 等で編集
- 依存を足したら `pyproject.toml` の `dependencies` を編集  
  必要なら「**requirements.txt を pyproject から更新**」

### 2.3 uv 環境 + インタプリタ

1. コマンド「**Python 環境を用意する**」（またはホームのボタン）
2. **まだ `pyproject.toml` が無いとき**（最初は普通）:
   - **プロンプトをコピー** → Copilot / Cursor チャットに貼り付け → AI が `nora/packages/pyproject.toml` と `main.py` を作成
   - または **雛形を自動で入れる**（NoraOps がテンプレを配置）
3. もう一度「Python 環境を用意する」→ 通知で venv パス → Python 拡張がインタプリタを設定

### 2.4 F5 で動作確認

1. `nora/packages/main.py` を開く
2. **F5** →「**NoraOps: アプリを実行 (F5)**」
3. ターミナルに `Hello from NoraOps!` 等が出れば OK

**セキュリティ（IP 直書き）の試し方**

1. `main.py` に例: `host = "192.168.1.10"` を書く
2. **F5** → **実行が止まる**（Problems に赤線）
3. 直してから再 F5。ルールは FastAPI `data/noraops/checks/security.rules.json`（再起動で反映）

コマンド「**セキュリティチェック（IP 直書き）**」でも単体実行可。

## 3. 保存 → Gitea

1. 画面下 **「保存」**
2. ダイアログで選択:

| 選択肢 | 意味 |
|--------|------|
| **新規 Gitea リポジトリを作成して保存** | 初回。FastAPI がリポ作成 → push → Runner 用 topic |
| **Gitea に保存（同じリポジトリ）** | 2 回目以降。main に push + topic |
| **新しいバージョンとして保存** | `pyproject` の patch を上げ、タグ `v0.1.x` で push |
| **この PC だけ** | Gitea に送らない |

3. 成功すると「**Gitea に保存し、Runner 用に公開しました**」→ **「アプリを使う」** で Runner へ

**うまくいかないとき**

- `write:repository` 無し → topic 付与失敗（push は成功していることがある）
- FastAPI / Gitea 未起動 → 503
- 設定の `gitea.token` が Host 側と違う

---

## 4. Runner：別ウィンドウ／別ユーザー体験

1. `noraops.mode` = `runner` **または** ステータスバー「**アプリを使う**」
2. 検索（空で全件、`DEV_SHOW_ALL=1` 時）
3. 対象リポの「**このアプリを使う**」
4. clone → `uv sync` → バックグラウンド起動（ターミナルに出力）

キャッシュ: `%LOCALAPPDATA%\NoraOps\runner-apps\`

## 6. よくある勘違い

| 質問 | 答え |
|------|------|
| 空リポだと Runner に出ない？ | **出る**（公開設定さえ満たせば）。中身は実行時に必要 |
| `portal/` を F5 する？ | **しない**。`ver1` または `vscode-extension` |
| 保存と Runner は同じウィンドウ？ | 同じ拡張。モードは `creator` / `runner` で切替 |
| requirements だけで uv は動く？ | **pyproject.toml** を `uv sync` が見る。txt は参照・AI 用 |
