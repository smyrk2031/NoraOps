# NoraOps 互換方針（旧レイアウト読み取り）

**正本**: [ワークスペース設計改定.md](./ワークスペース設計改定.md)  
**目的**: 改定実装中も **既存ワークスペース・既存 Gitea リポ** の Creator / Runner 動作を維持する。

---

## 1. 基本方針

| ルール | 内容 |
|--------|------|
| **読む** | 旧パスは解決ロジックに残す（削除しない） |
| **書く** | 新規・明示操作は理想形（ルート pyproject、AppData session） |
| **移す** | ファイルの物理移動は **ユーザー同意後** のみ |
| **消す** | 旧コードパスの削除は **互換期間終了後** |

**互換期間（初期案）**: 改定リリースから **2 メジャー minor**（例: v0.17 導入 → v0.19 で読み取り専用警告 → v0.20 で削除検討）。 exact バージョンは [実装記録.md](./実装記録.md) で確定。

---

## 2. パス対応表

### 2.1 Python 環境

| 項目 | 旧（現行） | 新（理想） | 互換 |
|------|-----------|-----------|------|
| pyproject | `nora/packages/pyproject.toml` | ルート `pyproject.toml` | **両方 probe**。新規 scaffold はルートのみ |
| venv | `nora/packages/.venv` | ルート `.venv` | **両方 probe**。`resolveExistingVenvDir` 拡張 |
| uv.exe | `%LOCALAPPDATA%\NoraOps\runtime\...` | 同左 | 変更なし |

**解決順（改定後）**

1. ルート `pyproject.toml`  
2. `nora/packages/pyproject.toml`  
3. venv: ルート `.venv` → AppData meta → `nora/packages/.venv`

### 2.2 NoraOps 契約

| 項目 | 旧 | 新 | 互換 |
|------|-----|-----|------|
| manifest | `nora/manifest.json` | 同左 | パス不変。スキーマ v2 は [manifest-v2-草案.md](./manifest-v2-草案.md) |
| entry | `nora/dev/main.py` 既定 | ルート相対 `main.py` 等 | 旧 entry 値はそのまま有効 |
| thumbnail | `nora/assets/thumbnail.png` | `assets/thumbnail.png` | **読取両方**。新規保存は `assets/` |
| packagesProject | `"nora/packages"` | 省略 or `"."` | 旧 manifest は packagesProject 維持 |

### 2.3 ローカル状態

| 項目 | 旧 | 新 | 互換 |
|------|-----|-----|------|
| session | `.nora/session.json` | AppData `workspaces/{key}.json` | **読: .nora 優先→AppData→書: AppData のみ** |
| python-env | `.nora/python-env.json` | workspaces 内 `pythonEnv` | 同左 |
| security-warn | `.nora/security-warn-state.json` | workspaces 内 | 同左 |
| runner log | `.nora/runner-last.log` | AppData（Runner キャッシュ側） | 低優先 |

### 2.4 greenfield 専用（①のみ）

| パス | 互換 |
|------|------|
| `nora/dev/` | 既存リポはそのまま。import / venv-only では **新規作成しない** |
| `nora/mock/` | 同左 |

---

## 3. サーバー・Runner

| 項目 | 互換 |
|------|------|
| save zip | 旧レイアウト zip も受理（`nora/packages/pyproject` あり） |
| `nora/manifest.json` + `appId` | **必須のまま**（サーバー registry） |
| artifact 内 venv | 引き続き除外。Runner は AppData `runner-envs/` |
| `giteaRepoId` 未登録 DB | nullable。初回 save / provision で backfill |

---

## 4. 移行トリガー（ユーザー明示操作）

自動でファイルを動かさない。UI で **提案** する操作のみ。

| 操作 | 内容 |
|------|------|
| 「新しい構成に合わせる」 | pyproject をルートへコピー提案、thumbnail を `assets/` へ |
| 「.nora を AppData に移行済み」 | 初回読み込み時にサイレント import（`.nora` は残しても gitignore 推奨） |
| 「旧 dev 入口を entry 更新」 | import プロファイルで `nora/dev/main.py` → ユーザー選択 entry |

---

## 5. テスト要件（互換ゲート）

最低限、以下をユニットテストで固定する（`test-01`）。

- ルート vs `nora/packages` の pyproject 解決  
- ルート vs `nora/packages` の venv 解決  
- `nora/assets` vs `assets` の thumbnail 解決  
- `.nora/session.json` 存在時の AppData 初回 import  
- 旧 manifest entry（`nora/dev/main.py`）の `resolveAppEntry`  

各 Phase マージ前: 既存 `npm test` 全通過。
