## 2026-05-24 — サーバー経由 Gitea push（拡張に PAT なし）

- **Phase 1 UX**: push 成功まで「Gitea に保存」と表示しない。失敗時は「この PC には保存済み・クラウド未完了」。
- **Phase 2**: `POST /api/v1/noraops/push/sessions`（短命トークン）→ `POST /api/v1/repos/push`（git bundle multipart）。サーバーが `GITEA_TOKEN` で `git push`。
- **Phase 3**: `app/noraops/auth/` — セッションストア（TTL）。将来 Windows/OIDC は `PushAuthProvider` 差し替え。
- **拡張 v0.4.0**: `serverPush.js` / `gitBundle.js`。`origin` URL に認証情報なし。`NORAOPS_CLIENT_EXPOSE_GITEA_TOKEN` 既定 OFF。
- **要件**: FastAPI ホストに `git` が PATH にあること。
- **まだ**: Windows ログイン連携、push セッションの Redis/DB 永続化、別リポ付け替え。

## 2026-05-19 — Gitea 403 read:user でカタログ空

- **原因**: `GITEA_LIST_MODE=instance` で `/user/repos` が必須 `read:user` なのに、トークンが `read:repository` のみ → 503 → Runner「承認済みアプリがありません」。
- **対応**: `gitea_client._paginated_repo_search` — 403 read:user 時は `repos/search` のみで続行。
- **利用者**: FastAPI 再起動。開発中は `.env` に `NORAOPS_CATALOG_DEV_SHOW_ALL=1`。本番は topic `nora-published`。
