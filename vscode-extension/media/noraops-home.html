💻 作る

モックと仕様をもとに、AI で Python アプリ（main.py）を作成します。

手順
  1. 「AI用の指示を作成」でプロンプトを表示して内容を確認
  2. 「プロンプトをコピー」→ 生成 AI チャットに貼り付け
  3. 返ってきたコードを main.py に貼り付けて保存
  4. 「作成したアプリを動かしてみる」→ 環境タブで Python 環境を用意
—

⚙ 環境

Python 3.11 + uv で仮想環境を用意し、アプリを起動します。

              置き換えテクニック（匿名化のヒント）
              
      
              プロンプトは AI チャットに送られます。モックの精度は操作の流れで決まるので、実名や社内固有名詞はダミーに置き換えて OK です。
              「実在しそうな名前」より、役割名・記号・「架空」「例示」の方が安全です。
              
      
                
        
              • 
          入れないもの
          本名・顧客名・社員番号・住所・電話・メール・マイナンバー・パスワード・API キー・未公開の社内資料の内容
        
                • 
        
              • 
          人名（氏名）— いちばん安全な書き方
          個人名は書かず、利用者A 担当者01 申請者（ダミー） 氏名（未入力） のように役割＋記号だけにする（おすすめ）
        
                • 
        
              • 
          人名 — どうしても姓名が必要なとき
          実在しうる「佐藤・山田＋太郎・花子」は避ける。架空 一郎 例示 利用者 テスト 申請者 のように、姓が「架空／例示／テスト／サンプル」だと一目でダミーと分かる。英字なら Example User
        
                • 
        
              • 
          行政・規格上の「例示用」ルール（参考）
          マイナンバー通知カード等の見本は架空の氏名・番号を使い「サンプル」と明示する（実在と混同しない）。電話番号は総務省の番号計画で、0X0 形式など資料用・未割当の並びが例示に使われることが多い（050-0000-0000 等）。メールはインターネット標準 example.com / example.org（RFC 予約ドメイン）のみ
        
                • 
        
              • 
          製品・部品・商品名
          部品A 製品X サンプル商品 のようにアルファベットや連番で
        
                • 
        
              • 
          会社・部署名
          A社 ○○商事（ダミー） 営業部 など汎用的な呼び方に
        
                • 
        
              • 
          生年月日
          カレンダー上ありえない日付や、明らかに例示用の日付に。9999-12-31 0000-01-01 1900-02-30（存在しない日）など。実在人物と重なりうる生年月日は使わない
        
                • 
        
              • 
          電話・メール
          050-0000-0000 03-0000-0000 / user@example.com（example.com はテスト専用）
        
                • 
        
              • 
          住所・ID・金額
          存在しない地番・架空の町名に。架空県見本市サンプル1-2-3 / ID-0001 / 123,456 円 など
