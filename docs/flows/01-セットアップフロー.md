# 01 — セットアップフロー

> **優しいメモ**: 「全部いっぺんに」やらなくて大丈夫です。**開発だけ**なら拡張 + ローカル API だけでも動きます。本番は段階的に足していくイメージで OK です。

---

## 1. 誰が何をセットアップするか

```mermaid
flowchart LR
  subgraph admin [運用・管理者]
    A1[Gitea]
    A2[nora-backend]
    A3[IIS ARR 任意]
    A4[pypiserver 任意]
    A5[許可リスト XLSX]
  end
  subgraph dev [開発者]
    D1[リポ clone]
    D2[nora-backend venv]
    D3[拡張 F5]
  end
  subgraph user [利用者 PC]
    U1[VSIX インストール]
    U2[設定タブ]
    U3[ツールセットアップ]
  end
  admin --> user
  dev -.->|ローカル試験| user
```

| 役割 | 最低限必要 | あると便利 |
|------|------------|------------|
| **運用** | Gitea、`nora-backend`、`.env` | IIS サブパス、社内 PyPI、バックアップ |
| **開発** | Python 3.11+、Node（テスト用）、VS Code | 同梱 `uv.exe`、`Gitea` ローカル |
| **利用者** | 拡張 + `noraops.server.baseUrl` | NoraAccessToken（本番認証） |

## 2. 本番セットアップ（運用）の流れ

```mermaid
flowchart TD
  Start([開始]) --> Gitea[Gitea 起動・管理者 PAT]
  Gitea --> Backend[nora-backend 配置]
  Backend --> Env[.env 設定<br/>GITEA_* / NORAOPS_*]
  Env --> Tools[data/tools に uv・PortableGit<br/>manifest.json 更新]
  Tools --> StartAPI[uvicorn または IIS 経由起動]
  StartAPI --> Health{GET /api/health OK?}
  Health -->|No| FixEnv[ログ・.env・Gitea URL 確認]
  FixEnv --> Health
  Health -->|Yes| IIS{IIS サブパス?}
  IIS -->|Yes| ARR[NORAOPS_ROOT_PATH<br/>NORAOPS_PUBLIC_BASE_URL]
  IIS -->|No| SkipIIS[ローカル直 8000 のまま]
  ARR --> ExtDist[VSIX を static へ<br/>client-latest.json]
  SkipIIS --> ExtDist
  ExtDist --> PyPI{pypiserver 使う?}
  PyPI -->|Yes| Mirror[pypiserver + ミラー sync<br/>許可リスト XLSX]
  PyPI -->|No| Done([利用者へ拡張配布])
  Mirror --> Done
```

**メモ（よくある順序ミス）**

- pypiserver は **`.env` だけでは動かない** → ミラー sync で `mirror/` に wheel が必要
- ツール配布は **manifest の sha256** が実ファイルと一致していること
- 本番認証は `NORAOPS_AUTH_MODE=email_token` が推奨（詳細: [認証モードとGitea運用.md](../../NoraOps/認証モードとGitea運用.md)）

**編集・参照先**

| やること | 見る場所 |
|----------|----------|
| 環境変数一覧 | `nora-backend/.env.example` |
| 導入手順の正本 | [NoraOpsの導入.md](../../NoraOps/NoraOpsの導入.md) |
| IIS | [IIS-ARR配備.md](../../NoraOps/IIS-ARR配備.md) |
| PyPI | [pypiserver 連携設定書](../../nora-backend/docs/pypiserverサービス連携設定書兼仕様書.md) |

## 3. 開発者セットアップの流れ

```mermaid
flowchart TD
  Clone([リポジトリ取得]) --> BE[cd nora-backend]
  BE --> Venv[venv + pip install -e .]
  Venv --> CopyEnv[copy .env.example .env]
  CopyEnv --> GiteaLocal{Gitea も試す?}
  GiteaLocal -->|Yes| GITEA[GITEA_BASE_URL + GITEA_TOKEN]
  GiteaLocal -->|No| ExtOnly[拡張のみオフライン可]
  GITEA --> RunAPI[uvicorn app.main:app]
  ExtOnly --> Ext[cd vscode-extension]
  RunAPI --> Ext
  Ext --> F5[F5 で Extension Host]
  F5 --> SetUrl[設定: noraops.server.baseUrl]
  SetUrl --> Try[空フォルダで Creator 試行]
```

**メモ**

- チェックルールはサーバーがいなくても拡張同梱 JSON にフォールバックします
- 保存・Gitea 連携を試すなら **API + Gitea 両方**が必要
- 手順の細部: [開発時用の動作手順書.md](../../NoraOps/開発時用の動作手順書.md)

## 4. 利用者 PC の初回セットアップ

```mermaid
sequenceDiagram
  participant U as 利用者
  participant VS as VS Code 拡張
  participant API as nora-backend
  participant LA as %LOCALAPPDATA%/NoraOps

  U->>VS: VSIX インストール / 更新
  U->>VS: 設定タブで baseUrl 入力
  opt 本番認証
    U->>API: メール登録 → NoraAccessToken
    U->>VS: noraops.accessToken 設定
  end
  U->>VS: ツールをセットアップ
  VS->>API: GET manifest / tools
  API-->>VS: uv.exe 等
  VS->>LA: runtime/tools に配置
  U->>VS: ワークスペースを開く
  VS->>VS: Creator / Runner パネル表示
```

**メモ**

- 利用者に **Gitea PAT は渡さない**（サーバー側 `GITEA_TOKEN` のみ）
- Python 環境作成時に **許可リスト warn** が出ることがある（続行可 → サーバーに audit）
