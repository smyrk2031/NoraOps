# 03 — VS Code 拡張の内部機能フロー

> **優しいメモ**: 入口は **1 本だけ** — `src/extension.js` → `noraops/activate.js`。ここから枝分かれします。  
> ファイル一覧の正本: [MODULES.md](../../vscode-extension/docs/MODULES.md)

---

## 1. 拡張の起動（activate）の流れ

```mermaid
flowchart TD
  Entry([extension.js activate]) --> Act[activate.js]
  Act --> Guard[registerRunGuard<br/>セキュリティゲート]
  Act --> Cmd[コマンド登録<br/>保存・Runner・設定…]
  Act --> UI[openPrimaryUi]
  UI --> Mode{getEffectiveMode}
  Mode -->|runner| RP[createRunnerPanel]
  Mode -->|creator| HP[createHomePanel]
  Act --> Defer[scheduleDeferredWorkspaceInit<br/>3秒後]
  Defer --> Rules[refreshRules]
  Defer --> WCheck[runWorkspaceChecks]
  Defer --> Launch[ensureLaunchConfig]
  Defer --> Gitea[refreshGiteaBindingQuiet]
  Defer --> Py[autoConfigureInterpreter]
```

**メモ**

- 起動直後は UI だけ先に出し、**重い処理は 3 秒遅延**（VS Code の体感を優先）
- ワークスペースが無いときもホームは出る（新規作成導線）

**触るとき**: `vscode-extension/src/noraops/activate.js`

## 3. Creator — 保存パイプライン（内部）

```mermaid
sequenceDiagram
  participant SB as statusBar / コマンド
  participant SP as savePipeline
  participant CH as checkRunner
  participant EP as entryPicker
  participant WZ as workspaceZip
  participant SS as serverSave
  participant API as noraopsApi

  SB->>SP: noraops.save
  SP->>CH: runWorkspaceChecks
  alt 失敗
    CH-->>SB: エラー表示・中断
  end
  SP->>EP: 起動ファイル解決
  SP->>WZ: zip 生成 manifest 含む
  SP->>SS: upload
  SS->>API: POST /repos/save
  API-->>SS: 結果
  SS-->>SP: 完了
  opt publish
    SP->>API: POST /repos/publish
  end
```

| 段階 | 主ファイル | 失敗しやすい点 |
|------|------------|----------------|
| チェック | `checkRunner.js`, `rulesClient.js` | ルール JSON 未取得 |
| 起動ファイル | `entryPicker.js`, `appEntry.js` | 複数候補・未指定 |
| zip | `workspaceZip.js`, `appIdentity.js` | `appId` / manifest |
| 送信 | `serverSave.js` | 認証・ネットワーク |

## 5. チェック（checkRunner）の内部

```mermaid
flowchart TD
  Start([runWorkspaceChecks]) --> Load[rulesClient ルール読込]
  Load --> Srv{サーバー rules?}
  Srv -->|Yes| Remote[GET checks/rules]
  Srv -->|No| Local[resources 同梱 JSON]
  Remote --> Eng[checkRunner エンジン]
  Local --> Eng
  Eng --> Sec[セキュリティルール]
  Eng --> Pol[repo-policy.rules.json]
  Eng --> Res[結果を UI / 保存ゲートへ]
```

**メモ**

- サーバーと拡張で **同じルール思想**（repo-audit もこのエンジン系を再利用）
- ルール変更時は [MAINTENANCE.md](../MAINTENANCE.md) の同期表を確認

## 6. Python 環境・許可リストの内部

```mermaid
flowchart TD
  PyCmd[uv add / sync / venv 作成] --> PE[pythonEnv.js]
  PE --> Resolve[pyprojectResolve / projectPaths]
  PE --> PAL[packageAllowlist.js]
  PAL --> Cache[allowlist キャッシュ]
  PAL --> API[GET packages/allowlist]
  PAL --> Audit[POST deps_audit 任意]
  PAL --> Warn{warn?}
  Warn -->|Yes| UI[続行ダイアログ]
  Warn -->|No| OK[そのまま進行]
```

**触るとき**: `pythonEnv.js`, `packageAllowlist.js`  
**サーバー側の対**: `nora-backend/app/noraops/routers/packages.py`
