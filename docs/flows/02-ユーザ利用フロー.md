# 02 — ユーザ利用フロー

> **優しいメモ**: NoraOps の「主役」は **ガードレール**（チェック・許可リスト）です。Creator（作る）と Runner（使う）はその上に乗る副機能、と覚えると全体像がブレません。  
> 製品像の正本: [製品像とロードマップ.md](../../NoraOps/製品像とロードマップ.md)

## 1. 利用者が見るモードと UI

```mermaid
flowchart TB
  subgraph shell [NoraOps 拡張 UI]
  direction LR
    ST[Setting 環境設定]
    CN[Connect API接続]
    PR[Prompt プロンプト帳]

  end
```

| モード / タブ | いつ使う？ | 主な UI |
|---------------|------------|---------|
| **Creator** | Python アプリを書いて保存したい | `noraops-home.html` |
| **Runner** | 公開アプリを起動したい | `noraops-runner.html` |
| **Prompt** | 組み込みプロンプトを参照 | `noraops-prompt.html` |
| **Setting** | サーバー・ツール・アカウント | `noraops-setup.html` |
| **Connect** | API 接続診断 | `noraops-connect.html` |

**メモ**: 設定 `noraops.mode` で起動時の既定パネルを切替。ナビでいつでも他タブへ。詳細: [07-モードと機能マップ](./07-モードと機能マップ.md)

## 2. Creator — 初回（新規アプリ）の流れ

```mermaid
flowchart TD
  Open([フォルダを開く]) --> Scaffold{NoraOps ワークスペース?}
  Scaffold -->|No| New[新規作成ウィザード<br/>scaffold]
  Scaffold -->|Yes| Home[ホームパネル]
  New --> Home
  Home --> Tools{uv ある?}
  Tools -->|No| Install[ツールセットアップ]
  Install --> Tools
  Tools -->|Yes| Venv[Python 環境作成]
  Venv --> Allow{許可リスト warn?}
  Allow -->|warn| Continue[続行 or パッケージ変更]
  Allow -->|ok| Dev[開発・実行]
  Continue --> Dev
  Dev --> Save[保存ボタン]
  Save --> Check[checkRunner ポリシー]
  Check -->|fail| Fix[修正して再チェック]
  Fix --> Save
  Check -->|pass| Entry[起動ファイル指定]
  Entry --> Zip[ワークスペース zip]
  Zip --> Provision{Gitea 紐づけ済み?}
  Provision -->|No| Name[リポ名決定 → provision API]
  Provision -->|Yes| Push[POST /repos/save]
  Name --> Push
  Push --> Done([Gitea に反映])
```

**メモ（ユーザーが意識しないこと）**

- zip は **拡張が作り、サーバーが解凍して git push** します
- 保存先は `.nora/session.json` の `giteaFullName`（将来 AppData 移行予定）
- チェック失敗時は **保存ボタンが止まる**＝ガードレールの核心

## 3. Creator — 保存・公開のシーケンス

```mermaid
sequenceDiagram
  participant U as 利用者
  participant Ext as 拡張
  participant API as nora-backend
  participant G as Gitea

  U->>Ext: 保存
  Ext->>Ext: checkRunner + entry 解決
  Ext->>Ext: workspaceZip 作成
  Ext->>API: POST /api/v1/repos/save (multipart)
  API->>API: manifest.appId 検証
  API->>G: 下書きブランチ noraops-draft へ force push（最新のみ）
  API-->>Ext: 成功 / エラー
  opt 公開する場合
    U->>Ext: 公開
    Ext->>API: save + publish=true
    API->>G: main に履歴付き commit + push（force しない）
    API->>G: 版タグ vX.Y.Z + topic nora-published
    API->>API: artifact zip 事前生成
  end
```

**Gitea ブランチの考え方（保存 vs 公開）**

| ブランチ | 操作 | 履歴 | push 方式 |
|----------|------|------|-----------|
| `noraops-draft`（既定） | 通常の「保存」 | 残さない（常に最新だけ） | `--force` |
| `main`（既定） | 「公開リリース」 | **残す**（v1.0.0 → v1.1.0 …） | 通常 push |

環境変数 `NORAOPS_SAVE_DRAFT_BRANCH` / `NORAOPS_SAVE_PUBLISH_BRANCH` で変更可能。

**編集するときは**

- 拡張: `savePipeline.js`, `serverSave.js`, `saveFlow.js`
- サーバー: `repo_save.py`, `repo_provision.py`, `app_registry_service.py`

## 4. Runner — アプリ起動の流れ

```mermaid
flowchart TD
  Start([Runner パネル]) --> Path{入手経路}
  Path -->|オンライン| Cat[GET portal カタログ]
  Path -->|オフライン| Zip[ZIP から追加<br/>契約検証]
  Cat --> Art[GET artifact zip]
  Zip --> Cache
  Art --> Cache[%LOCALAPPDATA%/NoraOps/runner-apps]
  Cache --> Dotenv[.env 同期<br/>runner-dotenv]
  Dotenv --> Sync[uv sync → runner-envs]
  Sync --> Allow2{許可リスト}
  Allow2 --> Run[GUI 起動]
  Run --> End([利用])
  Cache --> SC[デスクトップ SC 任意]
  SC --> Cmd[launchers/*.cmd]
  Cmd --> Standalone[VS Code 外起動]
```

**メモ**

- Runner は **git clone しない**（HTTP artifact または手動 ZIP）
- ZIP 取込: `pyproject.toml` + `nora/manifest.json` 必須 · `.env` は ZIP に含めない（`runner-dotenv` で別保管）
- ショートカット: サムネがあればアイコンに反映 · 表示名から `__app-*` ID を除去
- キャッシュ整理: Runner パネル「整理（ストレージ）」

## 5. ガードレール（主機能）の利用フロー

```mermaid
flowchart TB
  subgraph client [拡張・保存前]
    CR[checkRunner<br/>セキュリティ・ポリシー]
    PA[packageAllowlist<br/>uv add / sync 時]
  end
  subgraph server [サーバー・横断]
    DA[deps_audit 記録]
    RA[repo-audit 夜間/手動]
    ADM[/admin/packages 許可リスト]
  end
  CR -->|ルール取得| Rules[GET /api/v1/noraops/checks/rules]
  PA -->|照会| PKG[GET /api/v1/noraops/packages/allowlist]
  PA -->|違反報告| DA
  ADM --> PKG
  RA --> Gitea[(Gitea 全リポ)]
  RA --> CR
```

| タイミング | 何が起きる？ | ユーザー体験 |
|------------|--------------|--------------|
| 保存前 | `checkRunner` | エラーなら保存不可 |
| `uv add` 等 | 許可リスト warn | 続行可、サーバーに記録 |
| 夜間（任意） | repo-audit | 利用者は非同期、管理者が結果確認 |

## 7. 困ったときの分岐（利用者サポート用）

| 症状 | まず疑うところ |
|------|----------------|
| 保存できない | チェック結果パネル、起動ファイル未指定 |
| サーバー接続エラー | `baseUrl`、IIS サブパス、ファイアウォール |
| パッケージ warn | 許可リスト — 管理者に申請 |
| Runner にアプリがない | 未公開 or カタログ API · **ZIP 取込**を試す |
| ショートカットが動かない | `launchers/runner-launch.js` · 拡張再インストール後 SC 作り直し |
| オフラインで uv 無し | VSIX に同梱ビルド — [MAINTENANCE.md](../MAINTENANCE.md) |
| トークンエラー | NoraAccessToken 期限・再ログイン |

診断 UI: 拡張のヘルスチェック · サーバー `/diagnostics`
